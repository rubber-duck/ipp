# IPP coordination

Read `AGENTS.md` and `docs/development/coordination.md`.

Use a unique `BEADS_ACTOR`, inspect dependencies and current architecture, and claim a task before implementation. Inherited task descriptions must be reviewed against the accepted docs before use.

Architecture documents are the source of truth. Review architectural changes with the user and record accepted decisions there. `docs/plans/` contains only high-level implementation strategies that reference architecture.

Follow `docs/development/workflow.md` for claims, validation and handoffs. One sync owner checkpoints task history. Source commits and pushes remain explicit; task tooling does not authorize either.
