# Host composition boundary

The Host directly owns services, independently living Worlds, attachment reservations and completed publications. Worlds borrow graph and frame inputs only during a phase; they retain no Host or parent ownership. The [runtime](../../../../docs/architecture/runtime.md#world-attachments), [rendering](../../../../docs/architecture/rendering.md#outputs-and-composition) and [asset](../../../../docs/architecture/assets.md#retention-and-recovery) architecture owns the design.

`HostRuntime::frame` admits ordered mutation, resolves current topology, evaluates eligible Worlds parent-first, and assembles immutable outputs child-first. The attachment System admits ordinary producer component operations and extracts final placement and physical Surface constraints. A scoped frame context carries current placement, view and time, not a previous scene or child Canvas density. Producer attachment changes cannot alter a traversal during composed evaluation; removal cleanup remains synchronous.

Scoped constraints identify the exact local selected output; spatial contributions do not inherit the containing camera selection, and stale output incarnations constrain no replacement. A World's canvas applies physical Surface extent through its density, or viewport pixels divided by DPR when it is the selected root; otherwise its stored extent applies. Completed Surface edges retain the validated effective parent cache policy separately from child paint. Renderers use that policy only for optional Canvas caching, not to change explicit output mode.

Output producers may claim derived attachment placement through the read-only `System::attachment_placement` hook after local updates. The attachment collector joins a unique, live parent-output claim before spatial fallback: ready affine placement replaces Hierarchy, while unavailable, invalid or conflicting claims suppress the edge. The completed edge's `placement_output` scopes presentation separately from its selected child `output`; unscoped spatial traversal excludes these edges. Layout retains one derived placement shared with paint and inverse input, without changing authored Surface extent or introducing another attachment authority. A stale owning output invalidates frozen edge availability and cannot regain it through component replacement.

Explicit root selections and completed attachment traversal are presentation paths. Reading a historical publication or output does not select presentation. Exact World and output bindings fence runtime and component incarnations independently of durable metadata. Replacing a Camera requires an explicit new binding, including when its entity and output kind are unchanged. Camera publications own view-independent effective projection and affine pose; current view dimensions can reproject frozen inputs.

`HostRuntime::identity` exposes the existing runtime Host lifetime independently of Worlds or root bindings, including an empty catalog after teardown. Consumers can fence their own catalog bookkeeping without interpreting a missing World in an unrelated Host as destruction. This observation grants no token-construction or presentation authority and is not a durable identity.

One [`RootOutputBinding`](attachments/root_binding.rs) owns each root's selection, viewport and Host-fenced generation. Every successful explicit bind advances its identity, even when values are equal; publication refresh does not. Clear and destruction remove the record without reusing a generation. Root observation is independent of output availability. Ordered System command validation uses a read-only [`HostIngressView`](ingress.rs), reborrowed from existing command scope with command-specific foreign World declarations. It exposes current producer identity separately from retirement, exact output lifetimes and usable publication/resource leases, not a retained authored-state mirror or the latest-publication requirement. Systems still validate complete path/context and local readiness before mutation; no domain input execution branch belongs in the Host.

A branch whose evaluation or publication fails keeps its completed contribution. Incoming reservations outlive producer detach while any reachable available publication still contains the old edge, including a stale ancestor after publication failure. Publication retirement traverses usable edges only; safety invalidation retires unreachable history without waiting for another evaluation. A detached edge whose placement owner becomes inactive may retire even if that same output incarnation can later recover. Retirement is terminal for the exact attachment token: output correction cannot revive that edge or reacquire its old reservation. An unchanged active attachment keeps its token and reservation during recoverable output inactivity. Clearing a root selection does not discard a World's last output, since that output can still become an attachment contribution.

Ordinary attachment writes emit exact producer receipts in ordered batch effects, including successful same-value writes and effects preceding failure. Conditional detach compares that receipt without erasing another producer's replacement; both detached and superseded outcomes retain the original edge's retirement fence. Publications carry the same identity. A receipt owns only immutable identity metadata and a monotone retirement observation, never a Host, World or output. The Host retains active and publication-reachable metadata, not historical tombstones; native callers release terminal receipts by dropping their handles. Transport adapters must retain handles in bounded session registries, reject unknown or released wire identities, and drop their handles on explicit release or session teardown. Neither batch acknowledgement nor one frame implies retirement.

Selected Systems publish owned typed, versioned chunks through the generic output hooks. Unchanged chunks share immutable storage. Geometry owns separate visual, culling and picking results, including unknown conservative candidates. Render chunks own material properties, exact resource bindings, palettes, particles and lights; readers do not borrow mutable components. Publications acquire exact CPU/source leases before replacing preceding output. Resource invalidation suppresses the affected publication before release; the Host drains strengthened release revisions even when a branch is not evaluated. GPU residency and submission are separate consumers.

Hosts and native callers queue batches through `world_mut(..).enqueue`. Each batch applies whole at the next frame's mutation boundary, which borrows the foreign Worlds its commands reference; no borrow holds a World or its branch between frames.

This composition boundary is not a renderer or input router. Concrete Canvas output belongs to the GUI System; it is not synthesized from Camera or Surface state. [Graph persistence](../services/world_serialization/README.md) captures authored attachments separately from completed publications, preserving durable metadata through graph-local identities and publishing only complete private restores. Platform hosts, transport codecs and GL/GUI consumers must adopt these boundaries explicitly. `has_pending_world_updates` remains a logical preparation observation, not a CPU-release or graphics-device safety barrier.

The [headless composition tests](../../tests/host_composition.rs) exercise real camera, geometry, assets and ordinary component mutation. They establish CPU behavior only, not transport delivery, completed GPU frames or hardware performance.
