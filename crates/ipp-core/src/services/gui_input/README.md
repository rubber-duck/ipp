# GUI input service

This optional headless service owns input-session lifetimes, explicit root-context generations, immutable routed path proofs and bounded pending delivery tickets for routed physical input. A client's semantic action does not pass through it: it is a `GuiAction` batch command applied by the GUI System at its operation's mutation boundary, whose batch outcome is its result (see [GUI architecture](../../../../../docs/architecture/gui.md)). Its Host owns it alongside other services; it stores no Host pointer or authoritative control values. [GUI architecture](../../../../../docs/architecture/gui.md) owns input and machine-client policy.

## Boundary for the local receiver

`GuiSystemFactory` is the sole provider of `WorldOperation::Gui`: `GuiAction` commands need the local GUI System, not Canvas or layout. This manifest capability is not physical input readiness. Routed/native operations still require their selected producers, live root/context/path and owning input implementation. Omitting GUI from the selection omits the operation.

Adapters open a fresh internal session lifetime rather than reusing a wire session number. Root contexts bind the exact current `RootOutputBinding` and replace their generation even for equal values.

`reserve_routed` reserves metadata and delivery ownership with immutable routed provenance. It does not enqueue a command, perform pointer hit testing, execute GUI actions or claim local admission. Preparation rejects an effect whose source differs from the ticket's. On initial failure, `GuiInputReservationError::into_parts` returns the same response permit to the adapter for a bounded rejection or silent disposal after revocation; no replacement response allocation is necessary.

The GUI-owned non-Clone [`GuiLocalCommand`](../../world/systems/gui/local/command.rs) embeds the opaque `GuiInputCommand`. Its constructors require a routed ticket and matching target; raw actions are not executable System commands. It delegates its pure `System::command_world_references` declaration to the ticket. Before any local mutation, the [receiver](../../world/systems/gui/local/actions.rs) calls `validate(&HostIngressView)`, which calls `prepare(None)` before reading current authority. It separately validates exact control incarnation, action role, availability and eligibility.

After pure local validation and counter-overflow preflight, the receiver builds the exact immutable `GuiLocalEffect` from the current World mutation tick and core ancestry. Effect preparation invokes `prepare(Some(&effect))` before any effect mutation. The prepared effect's commit rechecks cancellation, invokes an infallible callback-free local mutation closure, then settles the existing permit. No external callbacks, additional World steps, reflow or further admission may occur inside that closure. Rejection has no synthetic effect tick. Dropping an unsettled command or uncommitted prepared effect cancels exactly once. Routed value operations write the control's fields through ordinary authored commands and settle as `Written { target, source, changed }`, without a momentary effect, because clients see the values through field subscriptions.

Routed `GuiLocalAction::Focus` and `Blur` use that same ticketed receiver and emit `FocusChanged { focused, changed }`, describing focus on the exact target. Routed Focus acquires or transfers exact service-session ownership, except on the control a `GuiAction` command focused: that focus keeps no owner, and routed Focus only changes its modality and gives a text input this session's native record. Routed Blur clears focus on this target unless a live foreign session owns it, which fails with local Unavailable rather than claiming it cleared focus; focus set by a `GuiAction` command has no owner and any routed Blur of its target clears it. If another target is focused, or none is focused, Blur applies an unchanged no-op. Focus/Blur use normal target/visibility/enabled checks and never imply native focus or platform capture; routed Blur retains its source/path/context fences.

Routed `GuiLocalAction::Submit` uses the same receiver for TextInput. Its application observation retains the exact committed text reference and pinned ancestry, without editing the value or moving focus. A changed incarnation rejects.

Capacity rejection at either preparation phase leaves focus and dirty state untouched. Reentrant session revocation also prevents the candidate commit; independent normal GUI evaluation still prunes the revoked session's prior focus. Read-only focus queries observe that liveness change immediately, not as an applied Blur effect. There is no second outcome queue or synthetic rejected-effect tick.

Routed reservation ties each command to its service session, root-context generation, target incarnation and attachment path. Each command independently validates and retains its own exact admitted source publication. Routed operations are relative or pointer-absolute and apply in order at the mutation boundary; delivery tickets keep their terminal outcomes without a revision. The router owns when to issue commands; the service neither predicts values nor queues events.

Routed validation checks the current root binding, context/session lifetime, selected output lifetimes, exact current attachment tokens, owner-output scope, live Surface eligibility and current ancestor policy. It reads still-available source publications and exact resource leases, not necessarily latest publications. Generic attached-publication availability alone is not path authority.

Current Surface and target ancestry must stay live and eligible up to the top level of their World, whose canvas contains them. An ordinary reparent within the canvas does not invalidate source provenance; the local receiver pins the actual committed ancestry in the prepared effect. Traversal borrows current entity links without cloning complete entity snapshots. None of these presentation-membership checks apply to `GuiAction` commands.

## Lifetime and adapter ownership

A root session can target child Worlds with no child authoring session. Session close revokes its shared delivery lifetime first, then cancels all its pending tickets across Worlds and returns native focus/capture cancellation records synchronously. GUI-owned logical focus set by routed input retains the exact service session lifetime, never a generic World session number; focus set by a `GuiAction` command has none and outlives sessions. Read-only focus queries observe revocation immediately; normal GUI evaluation prunes dead focus and invalidates its paint. Eligibility-only revalidation waits for the next evaluation, while exact target removal remains immediate. Adapters must invoke this service boundary in addition to their existing authoring-World teardown and must consume native cancellations immediately; this module does not own a platform event loop.

Physical presentation ownership is adapter-owned and independent of `RootOutputBinding`. Before switching or clearing a selected physical surface, losing its context or changing its viewport, the adapter calls `release_context` and consumes the returned native cancellations. Later `bind_context` calls mint fresh generations even when the root output and viewport are unchanged. An A→B→A physical selection must never reuse A's revoked handle; `GuiAction` commands are unaffected by presentation revocation. The real adapter selection-cycle scenario remains an integration requirement beyond this foundation's explicit release/rebind test.

Permit callbacks and payload destructors run without registry/record RefCell borrows. Reentrant cancellation during preparation marks the record terminal, then disposes or settles the temporarily extracted permit when preparation returns, before any local commit. Closed-session permits are dropped rather than externally delivered. Generic queued payload Drop on live World destruction settles Cancelled without another frame; it does not fabricate a WorldDestroyed cause.

The adapter supplies `GuiDeliveryPermit` backed by its existing bounded outbox. It reserves the response slot and bounded rejection bytes before offering the permit, grows capacity for the exact effect before mutation, and settles infallibly. Core has no host-session/protocol dependency or second outcome queue.

Only unsettled records remain indexed. Command metadata and action bytes, including shared text payloads, stay charged until the command drops, even after cancellation. Shared scope paths stay charged until their last command drops. Ticket-owned paths are charged separately. Repeated cancellation cannot hide retained storage from these bounded budgets. There is no permanent terminal map, per-control terminal history or committed-value mirror.

## Ordinary pointer feedback

`pointer_lease(&ticket, pointer)` reserves an inert `GuiPointerLease` for an existing routed ticket. A candidate neither steals an active pointer nor changes local pointer state. Failure rejects that existing ticket with its reserved delivery permit. Pass the lease to `GuiLocalCommand::interaction(ticket, lease, update)`; `GuiAction` commands cannot authorize feedback. The lease is clonable identity/cancellation metadata, not another control or pointer-state store.

`Hover(bool)` changes only hover. `Press` marks a press without activation or focus. `Capture` requires an existing press and denotes local logical capture, not successful platform capture. `Release` clears press/capture and retains hover; repeated release and identical updates deliver Applied with `changed: false`. `Cancel` clears feedback and permanently revokes that activation. A subsequent command using a revoked lease is rejected, not a new activation. These operations never toggle, replace a value, invoke button activation or move focus implicitly.

Empty feedback flags do not end an activation. When a pointer is finished, its runtime adapter must send `Cancel` and release retained handles; cancellation followed by final Drop releases the lease/path budget. Retaining an all-false activation until that explicit boundary is intentional, not passive lease garbage collection. Real adapter coverage must prove finished-pointer cancellation and subsequent budget reuse.

The receiver prepares `InteractionChanged` with exact pointer flags, identity, ancestry and mutation tick. It preflights dirty-counter overflow and record allocation capacity without changing observable state, calls the ticket's exact effect preparation, rechecks lease cancellation, then commits without callbacks or allocation. Only that successful commit activates/supersedes a pointer generation. A bounded shared pointer slot fences older candidates as well as old releases, including across target Worlds. A slot contains cancellation identity and its latest activation generation, never interaction flags, effects or a terminal history; it disappears when the last lease drops. Candidate, cancelled and active leases retain their lease/path budgets through last Drop.

GUI alone owns the sparse hovered/pressed/captured records. Same-Canvas reparent preserves them; local control removal, hidden/disabled/unavailable policy or a changed containing Canvas lifetime cancels permanently. An enabled local CanvasStyle clip with empty or reversed bounds on the control or an ancestor cancels at the local mutation boundary; correcting the clip cannot revive that activation. Positive clips and disabled clipping retain otherwise eligible feedback. Read-only pointer queries filter revoked session/context/lease ownership immediately. Evaluation prunes dead records and invalidates retained presentation. Committed values and logical focus are unaffected. The lease can survive new source publications: each new ticket still validates its own completed source and current path, but the persistent lease binds context, target and path rather than requiring recreation every frame.

`cancel_pointer_lease` is exact-generation safety revocation for the future composed runtime owner. It cannot cancel a newer lease and does not synthesize an action/effect tick. `GuiNativeState` continues to record platform focus/capture separately; local feedback does not mutate it or claim that the platform captured a pointer. Remote ancestor policy changes, attachment retirement and platform loss still require the composed runtime owner to revoke affected leases and release native ownership. Passive leases do not poll foreign Worlds. Command-time full path validation remains enforced; this slice does not claim autonomous composed cancellation or cross-World publication atomicity.

Canvas publishes all existing interaction-priority bits and resolves compact skin parts with disabled → pressed → hovered → idle precedence, retaining variants and control overrides. Pure feedback dirties presentation, not text measurement/layout. Equal resolved paint retains its immutable chunks and paint revision. No animation sampler, query descriptor, ray routing or native event loop is added; feedback is transient and excluded from graph persistence.

The compiled public-API fixture example is [`feedback` and its tests](../../../tests/support/gui_interaction.rs), included by `gui_controls.rs`. It binds an explicit root context, reserves a routed ticket, mints/retains a lease, constructs an interaction envelope, queues it to `GuiSystem::ID`, then observes a real Host frame and immutable Canvas publication. Its direct-root fixture uses an empty path; an attached renderer fixture supplies the exact completed attachment-token path instead. Renderer owners can exercise direct/cache capture against this public queue without a private GUI bypass or legacy fallback.

## Composed physical routing

`router::GuiInputRouter` consumes an explicit current view and completed Canvas/Camera observations. It queues ordinary delivery-reserved local commands through the owning Host, using exact attachment paths. It never advances evaluation. The physical context belongs to the surface owner, not to an authoring World session. Replacing its root/view or closing its connection revokes its queued commands and native ownership without destroying independent Worlds.

Adapters call `synchronize` at their existing routing boundary even with no new input; `None` denotes an unavailable view and cancels native ownership without manufacturing a frame. Pointer focus hides the focus ring except on text controls; keyboard/programmatic focus shows it. A control whose published record is not focusable is no traversal stop, and a press on it leaves focus where it is while it still takes pointer feedback and activates. Scroll hit records use the same deferred bar paint ordering and geometry as Canvas drawing.

The context's keyboard target is the logical focus of the Worlds it presents, however it was set. At `synchronize`, the [router](router/focus.rs) makes focus a `GuiAction` command set in a presented World its keyboard target: it blurs the previous target in another World and focuses the new one through ordinary routed commands whose terminals nobody awaits, so the next key, Tab and BackTab start from it and a text input gets this session's native record. A World that no longer focuses the keyboard target, as after a client blur, ends it and its native focus. A World with unsettled routed work of this context waits for a later boundary, so the context never mistakes its own queued focus for a client's.

A [group](router/group.rs) whose items take focus is one traversal stop, entered at its selected item or its first, and arrow keys along its axis, Home and End move focus among its eligible items through ordinary routed focus, with a routed select in a group whose selection follows. A group whose items do not take focus has an active item in the GUI System: pointer hover over an item makes it active, and the keys of a focused control outside the group move it with routed `ActiveItem` commands on the item and activate it with the item's ordinary press or toggle, Enter first, including a text input's native submit. A slider keeps its arrows, Home and End and a text input its Left, Right, Home and End; keys no group uses stay with the focused control and are unhandled where it has none. The group a focused control drives is one in the topmost open light or modal overlay of its canvas. The context records the active item it last moved until its World settles its routed work, so keys routed against one completed publication continue from it.

[Overlay modes](router/overlay.rs) read each presented canvas's open overlays in stacking order. A press of any button walks them from the topmost down, past manual overlays and hints, stopping at a modal one or at the first light one it lands in or in whose parent's subtree it lands; it closes every light overlay above and is then swallowed, reaching no control, panel or scene. Closing is a `GuiOverlayCommand` the overlay's World applies at its next mutation boundary by writing the overlay's `visible` field, as Escape's overlay step does for the topmost overlay that is not manual. An open light overlay's box and the canvas under an open modal one publish an overlay hit that selects no control, so presses, hover and the wheel do not reach beneath; the wheel's chain also ends at any overlay. Keys and native text edits to a control under a modal overlay are blocked, and traversal skips such controls and stays inside the modal overlay. Hints and their contents publish no eligible hits. The GUI System moves focus into an opening light or modal overlay and back to its invoker, publishing the focus changes of both controls, closes light overlays focus leaves and times hints on the World's frame delta; that focus has no owning session, so the context adopts it in its own modality.

A secondary press on an eligible control, and the Menu key or Shift+F10 on the focused control, are context requests: the router focuses the target as a press does and queues `GuiLocalCommand::context` with the press point in the target's canvas, or the bottom-left corner of the control's visible box for a key. The receiver publishes a momentary `ContextRequested` application effect and changes nothing else; clients decide what opens. Key and wheel input carry whether Shift was held.

Arrow keys step the focused value control in either orientation, Right and Up increasing and Left and Down decreasing; Shift selects its fine step. A wheel over the focused value control steps it once per event instead of scrolling, and over any other control, including an unfocused slider, scrolls as before, so a slider never takes the wheel from its scroll view by accident. The rule belongs to the value control rather than its presentation, so every presentation of the slider shares it. A press on a slider's thumb drags it from its grab offset; a press elsewhere on the control jumps the thumb to the pointer. A press on a dial leaves its value, and a drag turns it relative to the press along the vertical axis only, continuing from a bound it reaches ([dial geometry](../../world/systems/gui/local/slider.rs)).

Focus can name a part of a control. A control declares its focus parts in order ([`focus_parts`](../../world/systems/gui/local/control.rs)): a range slider's lower and upper thumb, a colour control's saturation-value field, hue rail and alpha rail when shown, and one part for every other control, which behaves as a control without parts. Each part is its own traversal stop, so Tab reaches a range's lower thumb, then its upper one, then the next control. The context's keyboard target and each pointer's target name the part; focus commands, the `GuiFocus` record and the `FocusChanged` effect carry it, a part change counts as a focus change, and the context adopts a part a `GuiAction` focuses. A pointer over, pressing or dragging a part of a control with several sends feedback naming that part (`GuiInteractionPart::FocusPart`), so paint and skin motion light only that part; over the rest of the control it names none.

A numeric text input's decrement and increment parts are no focus parts: they are pointer targets of the one stop. The router names the part a pointer is over or holds from the published [number geometry](../../world/systems/gui/presentation/publication.rs) (`GuiInteractionPart::Step`), and a press on one focuses the input, as any press does, and queues `GuiLocalCommand::number_part`, whose step and held repeat the GUI System applies on its World's Host clock ([numbers](../../world/systems/gui/local/number.rs)); the release or cancellation that ends the press feedback ends the repeat. Up and Down queue `number_step`, Shift selecting the fine step; Left, Right, Home and End stay with the text. Before blurring or moving focus away from a numeric input the router queues `number_commit`, so blur commits a pending edit. Escape queues `number_discard`, which reports the discarded text, instead of closing an overlay or blurring while the input holds a pending edit: the GUI System's record decides once the World has applied this context's routed work, and before that whether this context routed an edit of its text since it last committed, discarded or left it.

On a range, keys, Home, End and the wheel move the focused thumb, and a press takes a thumb ([`range_thumb`](router/routing.rs)): the one under it, or for a press on the track the nearer one, moved to the pointer. Where both thumbs are under the pointer, or a track press is as near to both, it takes the one that can move when both sit at one end of the range, else the last active one, the thumb focus names while the slider holds focus, else the one on the pointer's side. The thumb's routed commands, `slider_thumb` and `slider_thumb_step`, compute the new value at the World's mutation boundary from the current fields, clamped to the range and stopped at the other thumb, so a drag past the other thumb stops there and the thumbs never swap; Home and End move a thumb to that legal bound.

On a colour control a pointer addresses the surface whose zone holds it, each surface grown by half the gap to its neighbours, and the swatch is no part: a press there neither focuses nor changes anything. A press on a surface focuses it and sets its channels at the pointer, the field's saturation and value or a rail's hue or alpha, and the drag keeps setting only those, held at the surface's edges wherever the pointer goes ([colour geometry](../../world/systems/gui/local/color.rs)). On the focused field Left and Right step the saturation and Down and Up the value, and Home and End take the saturation to its bounds; on a focused rail the arrows step its channel and Home and End take it to its bounds; the wheel steps a focused rail only while the pointer is over it and scrolls elsewhere, the field included. The routed commands `color_channels` and `color_step` clamp at the World's mutation boundary, so every channel stays in 0..1.

The maintained `physical-webgl` and `physical-gles` scenarios exercise real browser pointer/key events, generated clients, transport, child-World controls, committed observations and captured pixels. The maintained [`gui-composites`](../../../../../tests/integration/gui-composites/README.md) scenarios drive client focus steering, context requests, groups, overlay modes, the slider's presentations and ranges, numeric entry and the colour control through the same real input on the native GLES and worker WebGL hosts; their README lists the parts. They do not establish OS IME or touch-device behavior.

The ordinary local [text receiver](../../world/systems/gui/local/text.rs) owns one sparse native focus record sharing the committed text Arc. Provisional composition and UTF-8 grapheme-boundary selection remain transient; they do not overwrite committed state or persist. Every native edit validates its exact target, focus/edit generation and routed authority. The candidate reserves its native terminal before mutation, publishes any immutable application effect before terminal settlement, and never advances evaluation itself. A direct client write to the text field is detected at commit by comparing text references; it resets the native record and advances the edit generation. The same measured text layout supplies glyphs, caret/selection paint and pointer placement; missing metrics never invent a caret position.

Pointer arbitration retains identities and gesture intent, not authored values. Content movement beyond the tap threshold disarms activation and forwards the actual delta through the existing innermost-first scroll chain. Re-entry cannot revive a cancelled tap, and a second press cannot steal the same held control. A hover that moves on before its feedback has applied revokes its candidate lease instead of queueing a Cancel, so its queued Hover settles cancelled and a burst of moves between mutation boundaries queues one command per move. Native platform cancellation and command-time lifetime validation remain separate from these local decisions.

Wheel and content-drag chains reserve every recipient ticket and FIFO position before release. Tickets retain their exact admitted publication through settlement, including resources and child publications, while continuing to validate the current context, path and incarnations. No latest-publication substitution or re-hit-testing repairs an old ticket.

An edit fenced for a control that no longer holds focus is rejected before routing. A fresh focus or action after a failure starts from its own validated observation, without rebasing or replaying any failed command.

Physical contexts accept an explicit bounded list of exact World/entity/PickingGeometry incarnations. The existing composed query applies transformed blocking; unmarked renderables remain transparent and replacement does not retarget a stale blocker. Secondary releases and auxiliary buttons receive correlated hit/miss results without borrowing primary activation. A panel is opaque to the scene: a press of any button on panel content that selects no eligible control is Blocked, not a Miss; a wheel it leaves unconsumed stays Unhandled for scene fallback. Scene wheel fallback is authorized only for a wholly unconsumed successful result, never partial consumption, rejection or cancellation. The protocol exports and hashes the full physical/native subformat, including nested layouts, key/button/edit discriminants and list widths, with the target contract.

## Validation scope

The maintained `test:gui:input-foundation` selection uses real Host queues, declared foreign borrows and destruction paths with an observing test System, plus focused budget invariants. `test:gui:core-lib` exercises the actual GuiSystem receiver, capacity-before-mutation and exact-session focus through real Host queues; `test:gui:core` retains ordinary control paint/lifecycle coverage. These are headless core proofs, not production transport/outbox, composed pointer routing, native input/IME or rendering integration. Those adapters must consume this boundary with their own maintained real-environment evidence.
