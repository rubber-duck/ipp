# Completed Composed Queries

These stateless readers join actual Camera, spatial and Canvas publications. They do not route events, own focus/capture, evaluate Worlds or admit GUI actions. A hit borrows the same finalized Canvas hit and optional GUI control observation used by paint. Its exact token path is input for the separate service's proof capture, never an input token itself.

Camera candidates use front-facing physical Surface planes, affine near/far distances and stable World/entity ties. Only explicitly named PickingGeometry blocks a panel; visual meshes do not. Distances remain in each containing Camera domain rather than comparing a nested Camera's distance with its parent. Canvas traversal follows reverse painter order, layer first, and finalized clipping, then maps through the published attachment slot into the child's published logical extent. A camera-domain Surface whose layer spacing separates its canvas's layers offers one candidate plane per layer in use, at its plane id times the spacing and holding only that layer's targets, so the ray meets planes nearest first and falls through where a layer has no eligible target; its canvas World is entered once per plane. No renderer target dimensions or live component values are consulted.

`query_composed_input` reports Hit, Blocked, Miss or Unavailable. A Camera ray that enters a panel Surface where nothing takes the point reports Blocked with the Panel reason and the nearest panel's path, never Miss; farther panels are still queried first. Unavailable Surface children block their known planes/slots. An unavailable Spatial contribution has no retained footprint, so the query conservatively reports Unavailable for that Camera domain. This may limit healthy sibling usability; it does not pretend to provide complete frozen-footprint routing. There is no caller work budget: the Host keeps attachments a tree, so a query enters each World once and its work follows the reachable composition. Explicit blockers are looked up by entity; unmarked geometry costs nothing. A World reached twice is an inconsistent composition and reports Unavailable, never Miss. Traversal is iterative and retains no permanent state.

`project_composed_point` reprojects an exact path for capture/drag geometry. Captured points may leave rectangles and clips, but must still intersect a front-facing plane inside the containing Camera's clipping interval; on a Surface separating layers that plane is the captured target's layer plane, or the plane of the nested slot the path continues through. Projection cannot claim or validate native capture. `CameraProjectionView` and the Camera view helpers expose the same physical projection domain for explicit nested picking/projection/navigation.

Root queries require exact current output and viewport. Bound queries additionally fence the exact root binding generation, including equal-value rebinds. With no publication constraint they select current completed state at execution, so ordinary gestures remain usable as the Host advances. With an explicit source they require that exact still-available publication; they never substitute latest. A source identity does not pin history. Historical queries remain explicit CPU observations, not proof of a completed draw. Root/context/session authorization and current local eligibility must still be checked by the action receiver.

The maintained `composed-queries` suite exercises real core publications, target-generated codecs and the gallery gesture controller through a native WebSocket Host with its autonomous clock. Its small pointer adapter supplies platform events, not World state or query answers. The GUI GLES publication scenario compares actual completed pixels, independently expected physical-aspect geometry and hit paths under device-limited raster allocation. These scenarios do not establish a complete GUI router, browser input or OS capture behavior.
