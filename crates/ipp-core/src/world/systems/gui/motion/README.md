# Ordinary GUI skin motion

[`GuiThemeMotion`](component.rs) adds sparse motion rows beside the `GuiTheme` selected by an ordinary `GuiSkin`. The component capability requires selected Animation and asset-dependency Systems; it does not introduce a reverse scheduling dependency. Static controls do not require selected Animation. Existing resource-bearing skin capabilities retain their asset-dependency requirements.

GUI resolves requests after ordered local mutation, before the frame's Animation pass. Part properties resolve independently through the existing base/state/variant chain, with per-control appearance overrides first. A motion destination needs resolved color, opacity and scale, plus alignment when the base part declares it. Consecutive typed clip tracks must match those resolved values at the authored sample time. Focus is a separate visibility destination: the same validated FocusRing appearance fades toward zero opacity on Blur, and toward its resolved opacity on Focus. The unfocused opacity uses an explicit constant destination in the AnimationSystem transition program, independent of the interrupted origin's restoration baseline; zero driver weight is not a hidden destination. Interruption retains the actual composite even when the first ready binding was already focused. The painter retains a fading ring after logical Blur, without retaining logical focus. Unchecked indicators without an explicit unchecked appearance fade toward zero opacity.

[`GuiSkinRuntime`](runtime.rs) contains only sparse, schema-ignored transition channels and a retained last-ready paint appearance for participating parts. It is not a second component or theme store. Generic fields, ordinary controllers and persistence cannot address its channels. Removing motion shows the current authored appearance. Read-only readiness distinguishes pending, ready and unavailable; it does not grant control or input authority.

[`AnimationSystem`'s private motion bindings](../../animation/gui_motion.rs) reuse its typed drivers and transition program. Interruption freezes the actual composite; no GUI sampler or second layout pass runs. Exact control and skin incarnations fence bindings before storage reuse. Payload unload releases prepared tracks and suspends elapsed time; explicit resource revocation withdraws the contribution. A pending replacement retains the prior ready appearance and source demand only within the same owner lifetime. Material properties adopt a ready destination; the source paint asset remains until its fade completes. Unchanged requests and settled samples retain output chunks without reflow.

Requested source identity and retained ready binding identity are indexed independently. Retiring the old binding cannot mark a different requested source unavailable, even if its readiness event already arrived. Revoking the requested source withdraws the contribution; a later source incarnation must become ready independently. Pending work sleeps until relevant readiness or declaration changes; settled bindings retain lifecycle/demand ownership but leave the sampling work set.

Preparation uses derived theme-reference and core-ancestry dependency indexes, not a second entity tree or copied theme table. Local commits dirty their exact target and displaced focus; cancellation checks dirty only tracked feedback participants. Unrelated camera, skin and style changes do not enumerate motion owners. Animation visits only changed or actively fading parts. Diagnostics builds expose actual latest-frame preparation/binding/sample counts through `WorldContext::gui_motion_work`; the maintained large-World fixture checks static, settled, unrelated-change and single-active-part work separately.

Membership retirement removes theme users, ancestry dependents and queued skin work at the core component lifetime barrier. Preparation and runtime mutation share a full-generational-entity/exact-skin-incarnation target resolver; an old dirty identity never obtains the replacement occupying its storage slot. Animation additionally checks the exact control incarnation before accessing private channels. These checks apply only to affected or active targets, not a new World scan. Real Host churn tests exercise deletion/reuse before preparation, same-incarnation theme edits and bounded retained indexes.

Theme dependencies use exact entity identities in sparse subscriber indexes. Missing required theme components notify subscribers even when their entity was deleted. Animation releases prepared bindings in the existing before-commit barrier, before GUI clears private channels in after-commit; its independent motion-demand lane is flushed there without waiting for evaluation. GUI queues only affected paint invalidations for the next permitted preparation. The last immutable publication therefore remains until the next evaluation while live motion bindings and channels are already withdrawn. Authored references, ordinary controller demand and retained publication resource leases retain their own owners and are not revoked by this cleanup. Valid pending replacements still retain their last-ready appearance; retargeting changes the indexed declaration dependency, so deleting an old theme cannot withdraw a newly targeted request.

Declared theme references are indexed at the commit boundary, independently of prepared motion requests and retained ready source bindings. Both GUI and Animation read only the staged theme field of each changed skin and update its exact dependency before processing theme invalidations, including changes in the same chunk. Retargeting does not sample, rewrite live channels, advance clocks or replace the frozen origin. Deleting the newly committed theme releases the old contribution immediately even when no preparation or Animation update intervened; deleting the formerly referenced theme leaves a valid pending replacement's ready origin intact.

Retargeting also retires the obsolete prepared request's readiness watch and active-work entry, not its retained ready binding. Late readiness or revocation of a formerly pending destination cannot poison the new declaration. Normal preparation resolves the new request and registers its source watch before the single Animation sample; retained ready source invalidation continues to use its separate bound-source index.

The declaration dirty marker survives a retarget round trip before preparation. Even when the final request equals the previously sampled request, it re-registers its readiness watch and active work while reusing the prepared binding and elapsed time. Settled unchanged work does not acquire another sample.

Source watches have a stricter validity boundary than sampled requests: before interpreting any resource transition, Animation reconciles affected watches against the current committed request inputs through its existing read-only GUI dependency. Lifecycle projection and normal preparation share the same per-part resolver. Whole-component and row edits to either theme table, skin overrides/retargets, control changes, local actions, inherited eligibility/tree changes and live interaction cancellation therefore cannot let an obsolete requested source revoke an independently retained ready binding. The existing GUI dirty/theme/ancestry sets, tracked feedback participants and event-key subscribers select the work; no World scan or extra preparation/sample runs. Only the requested source identity is reconciled at this barrier, not the sampled destination, appearance or committed control state.

An actual removal of the currently requested source still withdraws the contribution. Sparse request metadata retains that removal across an unprepared edit that resolves to the same source; merely changing duration or appearance cannot turn revocation into a pending ready-origin fallback. A new resource incarnation clears that marker through normal readiness resolution. Source-watch reconciliation queues bounded owner refresh for the next normal Animation update, including declaration/selector round trips, without restarting an unchanged binding. Retained ready source releases always act through the separate binding index, even when the requested source has changed.

Derived motion never enters the ordinary controller registry or its durable payload. Ordinary controllers keep their existing persistence contract. The maintained `gui:skin-motion` selection exercises real headless Host mutation, ticketed semantic actions, ordinary asset demand, Canvas publications and graph restore. Native/worker transport and GLES capture fixtures consume the same schema-generated declarations after the separately owned consumer snapshot is adopted; direct-core evidence does not establish those gates.
