# Lifecycle publisher

`LifecyclePublisherSystem` publishes owned observations of applied entity, component and asset changes. It owns subscription filtering and per-session queues; it owns neither loading nor synchronous invalidation. Slow clients cannot retain component or resource borrows. Ordinary evaluation does not publish lifecycle observations of authored component changes; value members observe stored values whoever wrote them.

Observations retain their effect tick and World sequence; filtering can leave sequence gaps. Failed batches preserve observations of applied changes. Subscriptions are session-scoped, do not replay history and are removed on session release. Unsubscribe discards matching queued observations; inspection supplies initial state when needed.

No count bounds lifecycle output. Every matching observation and membership record is kept in order and charged in bytes to the physical connection's reliable output account: targeted records when they are observed, filter observations when the Host drains them after each frame and pages them into responses. Exhaustion of that account fails the one connection loudly; no observation is dropped or coalesced and no subscription or membership is ended to make room, so other connections keep their delivery.

Indexed [target memberships](targets.rs) select exact entity generations or entity/component pairs and transition kinds before allocating output; value members (below) select component fields. [Indexes](target_index.rs) retain only live memberships, share targets across users and remove the target after its last member leaves. Hash lookup selects only the affected target; its ordered member map preserves deterministic delivery without enumerating unrelated targets. Unchanged frames do no membership work.

Diagnostic/test builds expose allocation-free [cumulative counters](statistics.rs). Index work counts one lookup per entity/component transition and exact-target candidates before kind/liveness filtering. Endpoint traffic counts only successfully retained events and their full reserved byte charges, including simultaneous payload/encoding capacity; ACKs and failed retention are excluded. Draining or removing records never decrements these counters. Saturation is sticky and disqualifies exact-delta claims. Closed or failed endpoints cannot supply live samples. Read-only copies carry no state mirror, replay, mutation authority or frame completion.

## Ordered membership and delivery

A Host creates a [LifecycleWatchOutput](output.rs) fixed to one World/session, using the physical connection's existing [ReliableOutputAccount](../../../services/reliable_output.rs). Member handles start inert. A [LifecycleMembershipCommand](membership.rs) owns an adapter-reserved reply lease and a page of members; enqueue it through the publisher's ordinary System command ingress without requesting a second generic command outcome. The sole typed ACK owns baselines captured at command application, including exact incarnation or absence, and retains its original request, World, session and member generations. It never rereads storage during delivery. Hosts reject a membership request on a World that does not select the publisher with an explicit unsupported reason before creating an endpoint, identically on native and worker hosts; a prepared command the World queue cannot admit fails the connection instead of settling as a silent cancellation.

The Host supplies peak encoded-allocation bounds, byte-pages requests and their baseline replies, and reserves reply capacity before admission. Core accounts command vectors, baseline capacity, retained records and endpoint/member handles; World-owned sparse indexes grow with active memberships rather than imposing a target-count quota. The public acknowledgement charge exposes target-native retained sizes; they are not wire sizes. Encoders must account their actual representation, spare capacities and simultaneous payload/encoding storage. `pop_front` transfers the payload and non-Clone lease together; the Host retains that lease through its outbox and delivery, dropping payload storage before reducing its charge. Account exhaustion is reported to the owning Host for connection-local disconnection.

Removing a member discards only that generation's observations still in Core's queue; queued ACKs and handed-off records remain owned and charged. Re-adding a target requires a fresh generation, so delayed removes and events cannot act on replacement membership. Cloned member handles share one registration; callers maintain their own last-user ownership before removing it. Distinct registrations can share the target index. Tracking ends only with session release, endpoint closure or connection failure.

Session teardown fences queued commands through `release_system_session`, retires active memberships and lets command destruction settle cancellation. The adapter also closes its endpoint, releasing queued delivery while preserving already handed-off leases. Ordinary root disposal first removes its memberships at acknowledged cuts, then closes the endpoint; this also avoids observing its own bulk declaration teardown. Output closure alone is delivery cancellation and does not substitute for World/session cleanup. Existing GUI effect output and unsubscribe drainage have a separate owning implementation.

## Value members

A value member names an entity, a component and ascending schema field offsets; rows, row properties and dynamic properties are not observable. Value members share member identity, Add/Remove paging, typed ACK cuts and the per-session output FIFO with lifecycle members, and their baseline reports the component's lifetime. The [index](target_index.rs) keeps them in member order apart from exact-target lookup. The Observe frame phase runs `System::observe_frame` right after every System's Finish, under the same fault gate, so [value observation](value_observation.rs) sees the final stored values of the evaluated tick. A new member has no last value, so the first Observe after its ACK reports the current value. Afterwards each Observe compares the member's fields with the values it last reported (text by pointer, then content; floats by bit pattern; other kinds by value) and emits at most one record carrying the tick. Absence of the entity or component is reported once. Unchanged members read their fields in place and allocate nothing; the work is one visit per value member.

Value records are state, not events. They are charged in bytes to the connection's account at observation, as are the retained last-reported values. A member holds at most one undelivered value record: a newer value replaces it, moves behind every record retained before it and takes over its lease, resized, so delivery stays in tick order. Account exhaustion, including a failed resize, fails the connection loudly. Removing a member and retirement discard its undelivered records with their leases. Lifecycle records are never coalesced, and ACKs and events keep their relative order.

The [Host drain](../../../../../ipp-host-session/src/session/lifecycle_watch.rs) holds value records back in Core while the transport has not completed the last value record it handed off, so a newer value supersedes an undelivered one in Core rather than queueing behind it in the outbox. It decides once per drain, so a transport that keeps up receives each frame's values immediately.

Clients register exact targets after receiving entity identities, await the membership ACK and then publish handles; the baseline supplies the exact incarnation or absence. Clients index pending and published handles by affected target and member generation, install listeners before sending membership requests, and prevent late ACKs from reviving cancelled or closed scopes. These are identity and value observations and acknowledged cuts, with no history, replay or application delivery acknowledgement.
