# Plot preparation

Plot consumes one entity-local completed data binding. The authored chart and its auxiliary frame remain in stable component storage; retained local geometry contains no authoritative component mirror. Multiple series select outputs of that one binding and contribute to one frame's bounds. The rendering architecture owns the boundary in [data visualization](../../../../../../docs/architecture/rendering.md#data-visualization).

[Components](component.rs) own schema and defaults. Frame component fields use ordinary scalar storage and expose `size()`, `min()`, `max()`, `color()` and `grid_color()` accessors. Series identity is the stable `Rows` slot. Label `row_id` is a canonical decimal u64 string because row properties do not have a u64 type; typed authoring accepts bigint and must stringify without Number conversion. Label offsets use local logical units in 2D and camera-right/down physical plane units about the data anchor in Cartesian 3D. Pie callouts use runtime-projected radial placement; authored offset magnitude adds optional radial clearance and its direction does not control their screen side.

[Prepared input](prepared_input.rs) borrows all selected rows, with exact `DataRowId` identities and explicit invalid expression results. Resolve selectors through `bind()` once per series, then call the resolved column's numeric/colour accessor inside sample loops. Algorithms never read source storage, reevaluate expressions or query a client observation page. Missing values make gaps/omitted marks; missing selectors and incompatible types fail preparation.

[Frame mappings](frame_mapping.rs) prepare a common linear range selected by the algorithm. 2D maps data +Y upwards into top-left/Y-down Canvas coordinates; 3D maps into physical [0,size] axes. Algorithms own automatic-bound expansion, baseline inclusion and chart topology.

[Percentage references](interpolation_reference.rs) resolve active interpolated scalar outputs through the chart's actual series selectors. A name may appear in several series on one axis; use on different axes is ambiguous, including hidden series. Grid bars use `value` for their Y axis; 2D bars and other Cartesian charts use `y`. Pie shares, colours and other outputs need an explicit numeric reference. The reference is the largest absolute endpoint of the existing pre-step fitted range, including baseline, spacing and degenerate-range expansion. [Retained evaluation](update.rs) supplies it to the binding-owned advance operation before its dirty skip, then prepares geometry and picking from the advanced display. Fixed-only and settled bindings request no fitting; a changed ambiguous association fails when interpolation next becomes active and suppresses prior geometry.

[2D algorithms](plots_2d.rs) and [3D algorithms](plots_3d.rs) expose pure preparation calls returning [compact local geometry](publication.rs). Algorithm authors own these files and adjacent descriptive helpers/tests; shared components, System integration, publication and renderer adapters have one foundation owner.

Generated paths contain closed quadratic contours in top-left/Y-down local plane coordinates. Stroke expansion and curve approximation belong to the algorithm. Paths reuse the shared analytic renderer, boxes reuse ordinary shape rendering, and text is measured by the shared font path using the same-entity frame's font source. Scene geometry uses compact retained triangle chunks with at most 65535 vertices and u16 indices; empty normals select unlit rendering. GPU data belongs to RenderService and is reconstructed from retained publications after context recovery.

[Retained evaluation](update.rs) acknowledges binding dirty only after geometry and requested fonts prepare successfully. Unavailable/changed source inputs suppress prior geometry. [Publication](publication.rs) leases font resources and local CPU output; the GL adapter keeps derived path/mesh storage only while a retained publication or current chart still owns its source, and rebuilds it after context recovery. Camera/transform edits reuse local streams. 3D axis/tick text has separate camera-facing planes at retained stations; annotation panels and connectors face together about their exact data anchor. Cartesian grids select far enclosure bounds for each composed camera, including opposite and below views, without reflecting coordinate bases. Cartesian axes prefer the front floor X edge, front left Y edge and upper left Z edge. [View placement](../../../../../ipp-render-gl/src/services/render/plot/view_placement.rs) estimates visibility from projected directions, viewport clipping and a cached content-only mesh enclosure; this bounded estimate can overestimate gaps between marks. Separate departure and return thresholds keep standard edges sticky. Renderer-owned drivers move line, ticks and title together along enclosure faces through corners, using Host presentation time, while streaming publications refresh visibility without restarting a live transition. [Plane facing](../../../../../ipp-render-gl/src/services/render/plot/plane_facing.rs) preserves physical text size, screen direction and ordinary scene depth. [Label arrangement](../../../../../ipp-render-gl/src/services/render/plot/label_layout.rs) keeps numeric text at its projected station in one compact lane beside the moving axis. It prioritizes visible endpoint stations and omits overlapping intermediate labels; current projected ink restores labels as room returns without retained hidden state. Titles use a bounded outward lane. Annotation panels retain stable local candidates and a small previous-offset preference scoped to the exact view and viewport. Pie panels extend along their projected slice bisector at the slice's own height, with radial-only collision candidates and panel-edge connectors; view history cannot retain a tangential offset. Moved panels retain data connectors through immutable unit strips stretched by presentation matrices. Crowded annotations keep their authored font size and use the least overlapping bounded candidate. Bar and cube edge strips and distinct face tones remain compact ordinary mesh geometry.

[Picking](picking.rs) uses compact analytic marks and original source-row IDs, independently of triangle rendering. Boxes and spheres reuse Geometry math; pies use exact radial prisms. Scene marks preserve affine ray parameters. Canvas marks use completed content placement, clips and painter order. [Host traversal](../../../host/queries/plot.rs) joins exact completed Surface attachments, and ordinary view fences protect root rebinding and retained historical queries. The common client pick result carries `component` plus optional `row: { series, rowId: bigint }`; querying a Canvas needs its selected Canvas System and does not force Camera/Geometry into a 2D World.
