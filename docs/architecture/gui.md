# GUI and Canvas Systems

[Architecture overview](../architecture.md) · [Runtime strategy](../plans/runtime-and-rendering.md#gui-implementation-approach) · [React strategy](../plans/react-reconciler.md#gui-declarations) · [Persistence strategy](../plans/ecs-serialization.md#gui-state)

## Ownership and scope

React and ordinary generated clients declare interface entities and application behavior. Selected GUI Systems own headless layout, interaction and immediate feedback and apply user actions to control fields; platform adapters supply native input services. GUI evaluates into retained [Canvas output](rendering.md#surface-presentation), without a React round trip or a second renderer.

Layouts, controls, styles and raw text/drawing/bitmap leaves are ordinary entities/components using the core ordered tree. In a World that selects the Canvas System they are content of [the World's one canvas](rendering.md#surface-presentation); a panel needing its own scope is its own World. A World may select GUI alongside other capabilities; there is no separate GUI World type or node-authoring protocol. A parent entity's Surface attachment presents exactly one child World: its canvas, or an explicit camera output. Surface dimensions and placement belong to the parent; the canvas's density and content belong to the child. Systems produce derived paint rather than issuing client commands to rewrite authored content.

V1 supports in-world panels, mouse/keyboard/touch, layout containers, text/drawing/image leaves, buttons, checkboxes, sliders and single-line text inputs. It includes semantic metadata, but no screen-reader bridge. CSS compatibility, arbitrary constraint solvers, screen-space windowing, XR, simultaneous independent viewers, rich/multiline editing, complex shaping/bidi/emoji, arbitrary in-plane clip transforms, momentum and multi-finger gestures are outside this scope.

## Identity and authoritative state

GUI targets use ordinary World-scoped generational entity identities and exact component incarnations. Reordering or reskinning preserves entity identity; removal, replacement and teardown invalidate property access, animation, interaction and pending work before reuse. Compact skin parts retain stable part identities independent of generated primitives. Layout consumes the core tree; delayed callbacks for momentary effects retain the logical ancestry recorded for their effect rather than reading a later tree.

Configuration, styling and control state use ordinary component fields and ordinary animation. Compact theme and part tables may use compiled rows, but entity structure and control identity do not live in parallel node tables. Committed values and scroll position, geometry and range are fields of the control component; inherited eligibility is on GuiBehavior and evaluated bounds on the system-written CanvasBounds. Every control therefore requires GuiBehavior and CanvasBounds, so a World authors controls only when it selects Canvas beside GUI. CanvasStyle is an optional override of placement, tint and clip; controls do not require it, and theme and neutral defaults supply their looks. Focus, pointer interaction and native text composition are GUI System state read through System queries. Layout, paint, hit regions and publications are reconstructible outputs. Numeric animation retains prepared access with lifecycle invalidation.

A control's value is an ordinary field that clients may write directly or change with compare-and-set; clients observe it by field subscription. Actions express user intent: relative operations, semantic value changes and focus, validated against entity/component identity and eligibility. Pressed and submitted are momentary effects. Runtime defaults are declared before input dispatch. Application callbacks observe committed changes and cannot retroactively cancel them.

Removing a GUI subtree explicitly removes its descendant entities through core lifecycle operations. Ordinary parent deletion retains the core non-owning behavior; React teardown deletes only the entities and components it created or adopted and cannot remove other children by implication.

## Layout and presentation

Constraint layout shares the [Canvas content convention](rendering.md#surface-presentation): a top-left origin, +X right and +Y down. Authored lengths are logical units. Each top-level entity is a layout root within the canvas extent. The canvas's units-per-metre density, [Canvas System state](rendering.md#surface-presentation), maps content to Surface metres and changes layout constraints without a GUI-specific axis flip. Output/view context supplies the canvas extent; Surface owns placement into parent space independently of camera motion. Layout components compose min/max constraints, flex and text measurement without an iterative cross-node solver or a Transform requirement on every GUI entity.

Animation precedes layout. Layout properties cause reflow; visual translation/scale move paint and hit regions together. Retained output changes only with relevant inputs. Camera-only changes update projection and placement without remeasuring text or reflowing the tree.

Paint and hit testing share evaluated layout, visual transforms and intersected rectangular clips. GUI prepares ordered parameterized shapes, glyphs, complex drawings and bitmaps through the shared Surface preparation boundary. Ordinary controls prefer [rounded-rectangle materials and retained presentation](rendering.md#gui-shapes-and-retained-presentation); RenderService owns coverage, GPU packing, glyph reuse and compatible contiguous batching under ordinary scene depth, transparency and colour rules. Layout supplies shape dimensions independently of corner and border dimensions. Decorative glow affects paint bounds only; it does not create a larger hit target. Missing resources affect their dependent work, and normal asset readiness/recovery rebuilds it.

A VirtualList is a ScrollView whose content extent derives from an authored item count and per-item extent estimate rather than from present children; a declared child's measured extent replaces the estimate while it is declared. The runtime owns its scroll math, clips and scroll bars, anchors the committed offset so measurements never move visible content, and writes the wanted item range to the control's fields when offset, viewport or measurements change. Explicit item-index components determine child placement independently of realization order; scroll-to-index uses the same model. Missing items never delay scrolling.

When content or item count shrinks, scrolling retains the clamped position and surviving visible anchor. Later growth never resurrects discarded out-of-range intent. Measurement changes preserve the visible anchor within the remaining scroll capacity; layout normalizes the stored position before publishing matching paint, without waiting for geometry to stop changing. Realized items remain ordinary entities in the containing Canvas World, not separate Worlds; the client declares and deletes them.

[Optional Surface texture caching](rendering.md#optional-surface-texture-caching) operates on evaluated paint under the rendering quality policy. It does not throttle GUI evaluation or input; focus and active interaction select current direct presentation so controls do not remain visually delayed by a distant cache's refresh cadence.

## Evaluation and input

GUI separates local mutation/control and layout through declared System dependencies, with input routing at the composed-view boundary. [The runtime schedule](runtime.md#frame-order) owns parent/child frame order; local selected passes remain fixed. AnimationSystem remains the sole sampler, including skin transitions.

Input arrives through ordered, session-fenced ingress for a presented root. Routing transforms rays/coordinates through spatial and Surface attachments against completed layout and camera/geometry publications, then queues ordered actions for the target World's next mutation boundary before animation. It does not mutate control values, reflow between events or recursively evaluate Worlds. Pending focus/capture/gesture decisions preserve input order. Actions revalidate the attachment path, entity/component incarnation and context; effects identify their source presentation/publication and target World effect tick.

Inherited eligibility, pointer interaction scope and focus scopes extend to the whole canvas and end at its World boundary. One active input context per presented root coordinates panels, focus and pointer identities across attached Worlds. Other clients may author or observe without acquiring input ownership. Uncaptured input selects the nearest eligible front-facing panel along the composed view path and reverse-painter eligible entity within clips. Explicitly marked picking geometry blocks input; visual occlusion alone does not. Comparisons use the containing view's distances and deterministic World/entity ties. Unavailable frozen output retains its occlusion without click-through. Captured input retains its target only while its full attachment path remains live; input for a removed capture target is reported unavailable. Unhandled input is observable for scene controls without duplicate dispatch. A panel is opaque to the scene: a press of any button on panel content that selects no eligible control is blocked, while an unconsumed wheel still reaches the scene.

Runtime interaction owns hover, press/cancel, capture, focus scopes and tree-order keyboard traversal across attached Worlds. With no focus, Tab and BackTab enter the nearest eligible panel by view distance at its first or last control; traversal continues across panels, with back-facing panels ordered after front-facing ones. Enter or Space presses a focused button and Space toggles a focused checkbox. Touch arbitration resolves tap versus slider/scroll drag and cancels the losing press; nested scrolling passes unused movement outward, and unconsumed movement is reported unhandled. Platform adapters convert wheel input to Canvas logical units before routing: the browser adapter counts wheel notches (100 CSS pixels, 3 lines or an eighth page each) and scrolls a configurable step per notch, a quarter logical unit by default. Hiding, disabling or removing a control, losing platform focus, detaching its path, and releasing/replacing an input context cancel affected interactions. The focus ring is focus-visible: keyboard and programmatic focus paint it, while pointer-press focus omits it except on text inputs. Session teardown fences queued work before identities can be reused.

## Text and skins

Text measurement and rendering share immutable font metrics and original glyph identities. Preserve Unicode source text and edit at grapheme boundaries, while rendering guarantees remain basic LTR Latin. Wrapping, glyph placement, caret and selection geometry use the same headless metrics. Runtime and browser text offsets require explicit conversion against the text they index.

Committed text is distinct from provisional composition. Single-line inputs publish a momentary submission effect outside composition. The platform adapter owns native focus, clipboard, IME, candidate placement and trusted-gesture soft-keyboard access; its temporary native buffer synchronizes through target- and focus-generation-fenced edits. An external change of the committed text invalidates delayed selection/composition and refreshes native state. Platform failure does not transfer text authority to the DOM or imply a successful edit.

Theme entities hold compact typed part tables with parameterized shape values, motion and immutable curve/font/bitmap/animation references. Controls reference a theme rather than copying its parts; per-control part rows retain only appearance overrides and live transition channels. Overrides take precedence over the resolved theme in every state/variant, and live channels take precedence while their transition owns them. Material values retain ordinary row-addressed field and animation ownership. Slider and scroll parts follow their committed values and evaluated geometry; thumb drag and track paging remain ordinary input. Resolve properties through disabled, pressed, hovered and idle precedence, with checked/value variants and a separate focus channel. Each property group has one animation owner. AnimationSystem transitions preserve interruption continuity; ready replacement preserves identity, focus and values, and pending replacement retains prior ready appearance only within the same control incarnation.

## Client and persistence boundaries

The optional `@ipp/react/gui` entry point produces ordinary entity/component declarations; browser composition stays in `@ipp/react/web`. Keys retain entities, refs resolve after acknowledgement, and render-time work has no transport side effects. Momentary-effect callbacks capture and bubble along the logical ancestor path pinned to their effect, including delayed delivery; value callbacks follow field subscriptions and bubble through React's own element tree. Callback-only changes issue no structural writes. JavaScript propagation controls only callbacks; native browser default policies must also be chosen before asynchronous runtime responses. [React composition](authoring.md#react-host-composition) owns declaration scopes and attached-World cleanup.

Clients read controls through ordinary component reads and field subscriptions, and focus and pointer interaction through GUI System queries. A client's semantic action is a `GuiAction` batch command naming the control's entity, component and incarnation; it applies at its operation's mutation boundary like any command, and the batch outcome is its only result. It is refused without effect, stopping the batch, when the target lifetime no longer matches (`StaleTarget`), the stored eligibility fields exclude it (`Unavailable`), the action does not fit the control role (`UnsupportedAction`) or the resulting value breaks the field's constraints (`InvalidValue`). Value actions are ordinary field writes observed through field subscriptions. Press, submit and focus changes publish momentary effects at that boundary, in ingress order, with the tick of the frame applying the batch. Logical focus set by a command has no owning input session: any client may blur it and closing a session keeps it. A semantic button press is momentary and neither commits a value nor moves focus. Routed physical input keeps its delivery tickets.

These reads, subscriptions and actions are the machine-client contract: autonomous agents and other programmatic clients observe and actuate GUI through them. Entity/part identity and invalidation before reuse survive visual-only change, so a reskin or relayout never retargets a handle; compare-and-set gives conflict-instead-of-overwrite where a client needs it. Record layouts follow the pre-stabilization policy and clients regenerate against their runtime. Platform accessibility adapters remain separate work; machine operability does not imply screen-reader support.

Component fields, including control values, follow existing [snapshot ownership](protocol-and-schema.md#snapshots-and-world-replacement). Focus, capture, selection, provisional composition, pending input/actions and GUI interaction playback are System state and are not saved. Restored Worlds reconstruct GUI output and use fresh runtime handles.
