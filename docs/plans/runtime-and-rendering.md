## Host execution

Extend shared session policy and native/browser adapters through generic Host/World interfaces. Compile attachment traversal at structural boundaries and separate parent-first evaluation from child-first output assembly and root presentation. Supply scoped parent/view context without retained World borrows. Multiplex independent World sessions while keeping presentation selection explicit. Use real clients to verify parent/sibling progress during an open child batch on the same connection, attachment publication, expiry, pause/resume, congestion and teardown.

## Evaluation strategy

Extend the [System lifecycle and dependency interfaces](../../crates/ipp-core/src/world/systems) under the [semantic schedule](../architecture/runtime.md#frame-order). Select dependency-checked immutable System compositions and preserve their local evaluation order. Keep instance results in components and subsystem bookkeeping in Systems; publish completed derived output with shared unchanged chunks. Test release barriers, frozen-branch safety and invalidation independently of update order.

Use maintained animation, hierarchy, skinning and mesh-pose fixtures before optimizing sampling or storage. Compare evaluated results with independent baked references. Extend bounds and picking together while keeping conservative enclosure distinct from interaction fitting. Additional pose-changing operations require the accepted dependency model; physics or iterative solving needs architecture review.

Compile real-time typed access and dependency selections at mutation/preparation boundaries, retaining work buffers and batching derived-result invalidation. Compare lifecycle, mixed-controller failures, pointer safety and independently sampled poses across native and WASM. Measure advancing updates separately from rendering; keep profiling opt-in and attribute by stable System/phase/composition identity under the [diagnostic contract](../architecture/runtime.md#diagnostic-logging), never compare selected schedules by positional slots.

Extend controller playback with signed clocks and explicit transitions under the [animation contract](../architecture/runtime.md#animation-and-constraints). Keep ordinary single-clip sampling efficient; prepare transition target unions, independent samplers and typed output access only while needed. Retain controllers' applied contributions and bounded interrupted origins through target or asset lifecycle changes. Extend core persistence and generated protocol/client contracts together, with observable transition progress and no client frame loop driving blending.

Use the maintained `animation`, `skinning`, `gallery-gui` and `snapshots` suites through real native WebSocket and worker/WASM clients. Independent numeric and joint-pose fixtures should cover reverse endpoints and loops, phase-aligned locomotion, partial gesture transitions, interruption, delayed assets and a saved interrupted fade. Completed WebGL frames and state/events must agree with independent sampling expectations. The Surface hover scene exercises a single reversible clip in a real pointer flow; existing drivers keep these scenarios independent of Host arrangement. Signed clocks and transition math also need focused core tests and malformed protocol coverage.

### Shared pure expressions

Extend the [pure expression boundary](../architecture/runtime.md#pure-expression-evaluation) with validated declarations, prepared input access and a contiguous execution sequence. Keep field resolution and scratch allocation outside repeated evaluation, and keep the operator vocabulary and detailed numeric rules beside the implementation. Share preparation and pure operations between driver and dataset consumers while preserving each System's binding lifetime, output ownership and schedule. Investigate scalar and block execution with measured dispatch, allocation and memory costs before adding specialized kernels or fusion; the shared evaluator must not depend on Plot or rendering being selected.

Extend maintained driver/animation and contract scenarios through generated clients in native WebSocket and worker/WASM environments, comparing independently calculated expressions, invalid declarations and replaced binding targets with observed results, reports and invalidation. Reuse local scene assets and completed WebGL/GLES frame assertions where expression-driven fields affect visible state. Focused core fixtures exercise scalar and row/block inputs, without standing in for Plot integration. Keep scenario semantics independent of environment launch and preserve failure artifacts and participant cleanup.

## Asset transport

Extend generic sources/readers/writers and Host adapters together through the [asset boundary](../architecture/assets.md). Measure copies and retained representations before adding transports or shared memory. Keep World dependency accounting separate from resource loading, including applied effects of failed batches.

Exercise client-authored sources over a distinct bounded data-plane protocol on both worker and native connections. Verify immutable names, complete-only publication, session fencing, interrupted delivery, payloads larger than command framing, and source progress while a logical command batch is still open. Retained publications use the [asset lease contract](../architecture/assets.md#retention-and-recovery); test source revocation, unload and recovery, including independently live sibling demand. Use the same resource lifecycle and image assertions as externally acquired assets.

Graphics providers receive narrow device dependencies at Host registration. Remove redundant representations only after identifying actual CPU consumers and recovery sources. Built-ins and new formats use ordinary ingress and lifecycle paths.

Separate loss of consumer demand from destruction of reusable loaded content. Add Host-configurable idle retention through the existing catalog and release barrier, accounting measured bytes and ranking pressure-driven eviction by both size and recency. Validate repeated clip selection without reacquisition, active/shared demand protection, forced pressure and session-private source teardown. Gate real browser asset delivery while observing advancing animation poses and completed frames; fast local fixtures alone cannot establish smooth mode changes.

## Rendering and recovery

Extend shared WebGL/GLES preparation and renderer-owned loading to consume completed World publications. Compose spatial descendants into one camera/depth/light/transparency domain with World-qualified draw and hit identities. Prepare nested camera color/depth targets before parent Surfaces and preserve direct Canvas presentation. Test parent lights on child meshes, child shadows on parent receivers, cross-World transparent ordering and transformed picking. Keep light selection, shadow allocation, material packing and device limits private to rendering.

Exercise completed frames under resource delay, allocation failure, material fallback and actual context loss, including frozen publications whose authored components have changed. Distinguish draw/resource failures from context, World and Host failures. Verify usable CPU interaction and healthy Worlds survive graphics failure. Port custom materials, skin palettes and particle inputs into publication consumers together so no submission reads changed live World state.

Retain prepared geometry, material state and draw records through versioned publications. Compare flat and hierarchical queries against identical conservative candidates and completed frames; use explicit view targets and distinguish World evaluation from output presentation completion. Verify cache reuse and invalidation through resource, component, attachment, World and context lifecycle changes. Benchmark/profiling runs in the [performance harness](../../tests/performance/README.md) stay outside regression; bounded correctness scenarios such as the registered `gui-stress` suite remain normal integration coverage.

Inspect resolved features and measure WASM, JavaScript/shaders and native shims separately against their size budgets. Verify that declarations of a capability a World did not select fail at both direct-core and protocol admission, and that small Worlds avoid unused storage and renderer resources. Validate packaged shims under the [workspace policy](../architecture/rust-workspace.md); compilation alone does not establish delivery.

Use the Python pipeline's declared products, shared executor and selected environment checks for all maintained commands. Keep routine regression bounded to core correctness and add affected subsystem suites through the same graph; broader distribution matrices, platform scenarios and scaling checks remain explicit on-demand selections under the [validation workflow](../development/workflow.md#validation). Keep Node operations limited to their actual JavaScript/WASM work. Validate clean-checkout prerequisites, matching generated targets, per-run manifests, failure/cancellation cleanup and representative native/browser/GLES scenarios. Build products may be reused by scenarios and examples without coupling their fixture bundles. Keep source and environment identity explicit before reusing validation evidence.

## Surface implementation approach

Move raw Surface authoring and GUI onto ordinary Canvas entities under the [shared content convention](../architecture/rendering.md#surface-presentation). Preserve glyph placement, drawing/bitmap orientation, clipping, animation inputs and plane interaction while moving density and content into the child World. Regenerate affected clients, examples and fixtures directly. Use asymmetric content and independent corner/line-position assertions through real native/worker clients and completed WebGL/GLES captures to expose double flips, winding errors and hit/paint disagreement.

Use entity/component/link mutation for Canvas leaves, retaining compact glyph/vertex/part data where appropriate. Compile property bindings independently of painter's order, retain headless string layout and externally positioned glyph runs, and reuse immutable converted font/drawing resources. Preserve RGBA bitmaps, rear-view mirroring and rectangular clipping through the shared WebGL/GLES path. Explicit attachment modes must become unavailable when required Surfaces or outputs disappear, without changing projection implicitly.

Keep item edits proportional to affected content and properties. Retain prepared glyph and renderer data across unrelated camera or style changes, preserve painter order, and invalidate retained data before identities or resources are reused.

Implement [GUI shapes and retained presentation](../architecture/rendering.md#gui-shapes-and-retained-presentation) by extending the existing box primitive and stable skin parts. Carry evaluated shape dimensions and bounded fill, border, gradient and glow inputs through the shared preparation boundary; regenerate target-correct authoring contracts and preserve ordinary animation ownership. Add each contour or fill as a paint mode of the shape program that reuses record lanes another mode leaves unused, as stroke marks reuse the corner lanes, so the shape record keeps its size; a further lane costs every shape quad its bytes, so add one only where a use exists. Arcs keep an exact distance so antialiasing and glow follow their caps; dashes, colour fields and the checker filter by the fragment footprint so oblique and minified Surfaces do not alias. Use instanced per-quad records, with narrow outline/corner coverage where it saves fragment work; large rings are the first candidates for sparse coverage. Keep the current SVG/quadratic and bitmap paths interoperable in the same ordered stream, without converting ordinary controls into mutable drawing assets. Captures of colour fields assert sampled sRGB values against independently computed colours, not only regions. Generate the canvas shape program from its static source and the [custom paints](../architecture/rendering.md#gui-shapes-and-retained-presentation) in use, so painted boxes keep batching with ordinary shapes and a paint that cannot run falls back to its box's colour with a diagnostic naming its entity; capture painted panels, a failing paint and a property animation on both renderers.

Implement canvas layers inside Canvas evaluation: resolve plane ids down the existing traversal, raising each nonzero layer above its parent's plane, order paint and hits by a stable plane sort, and restart clip scopes at raised entities, keeping keyboard traversal and effect ancestry in tree order. Carry each primitive's plane id through publication beside the ascending planes in use, keep each retained range within one plane, and offset each plane's draws by its id times the Surface's spacing, so animating the spacing changes no retained geometry and a plane never moves when another comes into or goes out of use. Extend the composed input query to intersect the planes in use nearest first, and grow the renderer's Surface culling bounds to the highest plane in use. Select direct presentation while a canvas using a plane above the base has a nonzero spacing, and add the per-pixel plane mask to cached images when a cached exploded panel needs it. Prove that a canvas without layers publishes the same order and pixels as before and that a plane keeps its depth while another opens and closes, and capture exploded Surfaces from oblique and rear views, with a gap where a plane is unused, and real pointer input landing on raised content.

Port the skin lab's distilled rows into the [built-in looks](../architecture/gui.md#text-and-skins) and keep the lab specimens as their reference; the maintained default-skin scenario asserts them on native GLES and worker/WASM/WebGL. New controls and composites add their looks there rather than in examples, and a default-skinned control publishes only boxes and glyphs.

Retain CPU geometry by primitive identity and material/geometry revision, and replace complete changed GPU batches while preserving storage used by queued draws. Start with device storage replacement and measure an explicit pool only if needed; avoid assuming orphaning guarantees stall-free allocation or that a fixed frame delay proves storage reusable. Choose bounded batch granularity so cursor or control animation does not rebuild every panel. Batch boundaries must preserve clipping, painter order and resource compatibility; camera placement updates use shared transforms.

Implement [glyph presentation](../architecture/rendering.md#glyph-presentation) with shared coverage atlases populated from existing font contours and explicit glyph triangles. Reuse headless metrics and positioned runs. Compare raster resolution bands against direct curves using actual small-text and oblique-view captures before choosing defaults; preserve current analytic fallback. Keep atlas locations stable while referenced, pad/filter entries without neighbour bleed, and invalidate dependent geometry before eviction or reuse. Batch cache misses and bound generation/allocation work. Evaluate MSDF separately if the required scale range warrants its generation and shader costs; neither path implies full Unicode shaping or Ghostty integration.

Implement [optional texture caching](../architecture/rendering.md#optional-surface-texture-caching) behind the shared RenderService/device boundary, using a whole Surface as the unit of rasterization and repaint. Extend prepared inputs with enough content identity and interaction priority to distinguish paint changes from placement changes without a second authoritative GUI store. Cover raw Surface and GUI output, including transient paint and asset readiness, through the same invalidation boundary. Reuse the ordinary curve, bitmap and box rendering paths to build GPU images without CPU readback, and composite them with the existing Surface placement and transparency rules.

Use configurable camera-distance bands to select direct presentation or cached resolution and refresh cadence, with stable mode transitions. Coalesce changes until a refresh is due and keep eligible focused or actively interacted-with GUIs direct. Bound image allocations and preserve direct Canvas rendering as a fallback. Key content reuse and glyph demand by presented publication while current parent views select quality; rebuild from retained publications after context recovery. Keep detailed policy values, allocation algorithms and API fields beside the implementation.

Use converted local font/SVG fixtures and a terminal-style scene through generated browser and native clients. Combine state and mutation-count assertions with completed WebGL/GLES captures for incremental edits, animation, lifecycle, persistence, delayed resources and recovery. Measure unchanged, camera-only and item-edit workloads separately from asset preparation; keep hardware timing separate from deterministic work counts.

Extend the maintained GUI gallery as the showcase of every built component on the default looks, with an exploded view of its panel layers, covering resized borders, gradients, localized glow, small labels and font icons on retained shapes and glyphs, with complex artwork such as waveforms kept as curve drawings in the same Surface. Exercise default, hover, press, focus and disabled paint through existing controls and Host-driven animation. Through production worker/WASM/WebGL and native/GLES drivers, assert meaningful completed-frame regions, clipping, overlapping transparency, paint/hit agreement and context recovery, including mixed shape/text/curve order. Keep fixtures owned by examples and scenario assertions independent of launch and wire layout. Record retained batch rebuilds, uploaded bytes, glyph misses and resident bytes through narrow diagnostics, with zero unchanged-content uploads after warmup as an observable invariant.

Extend the maintained terminal fixture with viewport-bounded glyph runs, typing, cursor blink, scrolling and full-screen updates, reusing atlas entries across repeated panels. Coalesce paint preparation to rendered frames while preserving all semantic updates. Compare warm and cold caches, idle and continuously changing scenes, sparse and full geometry updates, and bounded memory under churn. Use controlled camera/viewport/DPR and report source, device, OS/browser, warmup and interval identities. Real iPhone measurements establish mobile performance; software graphics and frame-cadence counters alone do not establish GPU timings. Partial Surface damage redraw remains a measured follow-on: it must account for old/new glow bounds and replay intersecting content in order, including the bandwidth cost of preserving target contents.

Extend that harness with near and distant Surfaces containing static labels, translucent overlapping drawings, clipped controls and Host-driven animation. Drive distance and focus transitions through production clients in worker/WASM/WebGL and native/GLES environments, and compare completed frames with direct presentation at controlled states. Observe cache dimensions, repaint counts and resource lifetime through narrow diagnostics; prove content reuse, distance-dependent quality, current interaction feedback and continued World progress. Reuse the scenario assertions across environment drivers, retain failure captures and clean up all owned participants. A repeated-panel performance fixture should record real device identity, rendering work and memory alongside timing, so software-rendered correctness is not presented as mobile GPU performance evidence.

## GUI implementation approach

Implement the [GUI boundary](../architecture/gui.md) with ordinary entity/component declarations, the core ordered tree and selected local control/layout Systems. Preserve incremental typed access and retained algorithms while removing GuiRoot node ownership and the separate structural protocol. Retain compact theme/part tables and shared theme references. Publish coherent link, attachment, output and control-state interfaces before dependent consumers migrate. Route composed input into next-boundary actions without mutable cross-World references or additional animation samples.

Retain headless font measurement, constrained wrapping and grapheme/caret mappings. Prepare layout, paint and hit regions from the same evaluated inputs, intersect rectangular clips once, and preserve ready output across unrelated changes. Carry control fields, actions, VirtualList measurement/anchoring and last-ready theme transitions through ordinary entity lifecycle. Extend explicit subtree removal without changing core non-owning parenting or React's deletion of what it created.

Build [controls and composites](../architecture/gui.md#controls-and-composites) as small extensions of the existing controls and router rather than per-component controls. Let the router derive its keyboard target from logical focus, so a command focus needs no second focus record, and keep groups, active items, overlay invokers, delays and part focus in GUI System state beside focus and pointer feedback. Generalize the scroll bar's part hits and part interaction to range thumbs, colour surfaces and numeric step parts instead of adding a mechanism per control. Resolve an overlay's placement from its anchor's evaluated placement in the same evaluation, without an extra frame or iterative pass: lay it out after the pass that places its parent, measure its content, and lay it out again limited to the room only on an axis its content exceeds; on frames without layout work, recheck the inputs its placement read so a moved anchor or an opened overlay is placed before that frame's paint. Drive delays and held repeats from the Host frame delta, and make a Host that renders on demand keep frames coming while one is pending. Group moves past a VirtualList's realized range use its index-based scrolling; measure before adding focus by item index. Each extension lands with its default look, its lab specimen and its kit component, so the gallery can show it as it arrives.

Time [skin transitions](../architecture/gui.md#text-and-skins) with motion rows resolved along the same part chain as appearance, writing each request into schema-ignored channels that AnimationSystem alone samples on the Host clock, so static and settled controls cost no per-frame work. Drive the built-in looks' transitions through real input on both renderers and assert each captured sample against the eased interpolation over the Host time around it, with reduced motion snapping them, beside the core's work counts for static, settled and changing controls.

Extend the maintained GUI scenarios through real routed pointer and key input on worker/WASM/WebGL and native GLES, with completed-frame captures beside state and effect assertions. Cover an overlay over later siblings and outside a scroll clip, flipping at the canvas edge, an outside press swallowed without click-through into another control, panel or the scene, Escape closing the topmost overlay and returning focus to its invoker, a modal dialog blocking its canvas but not a sibling panel, arrows and a single Tab stop in a group, an active item moved by keys and hover while a text field keeps focus, reveal in scroll views, a command focus receiving the next key, a context request at its canvas point, a tooltip delay counted in Host frames, and held repeat. Keep the assertions independent of launch and transport so new Hosts reuse them.

Extend maintained native WebSocket, worker/WASM/WebGL and GLES drivers with generated clients, real React declarations and local font/drawing/bitmap/clip fixtures. Exercise nested Canvas/Camera outputs and spatial scenes, cross-panel keyboard traversal, transformed blockers, captured input and detach/reattach. Assert publication/source revisions, effect ticks, compare-and-set conflicts, logical-focus revalidation and independent hit/paint geometry alongside completed images. Register lasting scenarios in suite/build catalogs; keep unchanged-frame, camera-only and local-edit work counts distinct from timing.

Keep browser input adapters reusable with a plain generated client. Delay application callbacks while actual ingress continues to prove runtime ownership. Extend browser drivers for resize, capture, focus loss and composition; retain separate actual OS IME and touch-device soft-keyboard evidence, since synthetic events cannot establish those platform behaviors. Future process arrangements reuse scenarios through new drivers. Follow the common harness policy for readiness, frame barriers, failure artifacts and cleanup.

Measure GUI changes with the real React [GUI stress benchmark](../../tests/performance/gui-stress.md). The benchmark guide owns workload definitions, metrics and separate timing/capture/profiling windows; new composition-only workloads supplement rather than replace it. Compare revisions by running each committed revision on matched verified hardware and settings. Performance acceptance preserves the scene's observable work and retained incremental behavior, with measured costs rather than assumed neutrality.
