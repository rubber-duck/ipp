# Cockpit authoring

[cockpit-projected.blend](cockpit-projected.blend) is the active scene. The fixed-size console uses a complete [restyled cutout](console-matched-base.png) derived from the approved [reference](cockpit-reference.png), with rounded endcaps and a finished apron. The bridge owns the console, integrated instrument mounts and carousel mount; changing viewport aspect changes camera framing, never their dimensions or relative placement.

[project_cockpit.py](project_cockpit.py) builds the scene. [spatial_environment.py](spatial_environment.py) maps the generated transparent-window panorama onto a fixed inward-facing sphere and adds the oblate planet, atmosphere shell and distant sky. The pilot sits behind the sphere's center, exposing more of the surrounding artwork in the forward view; shrinking a sphere centered on the pilot would leave its apparent scale unchanged. The shell's dimensions and placement never depend on viewport aspect. Horizontal background dragging turns the camera around its vertical Y axis at the pilot's fixed seat; the bridge and dashboard stay in place. Landscape viewports keep the same vertical field of view, revealing additional side architecture as width increases. The runtime supplies planetary illumination, independently drifting clouds and slow rotation through ordinary custom materials and Host animation. [standalone_console.py](standalone_console.py) places the console and registers its independently animated lamps. Native GUI surfaces occupy the authored empties; Blender preview outlines never export.

The [source panorama](bridge-panorama-v2.png) and its [imagegen prompt](bridge-panorama-v2-prompt.txt) are retained. [prepare_bridge_tiles.py](prepare_bridge_tiles.py) splits its original pixels into four quadrants before imagegen enhances each one independently. The active `bridge-<quadrant>-fixtures-base.png` images restore visible unpowered diffusers; each has its exact `*-prompt.txt` beside it. The dashboard uses the [matched base](console-matched-base.png) ([prompt](console-matched-base-prompt.txt)), retaining the original console silhouette and instrument mounts. Earlier base/emission image pairs remain provenance and are not runtime lighting inputs. Imagegen adds plausible detail; it does not recover measured original detail.

[lighting_tiles.py](lighting_tiles.py) builds grayscale contribution maps from [registered fixture outlines](lamp_fixtures.py). A small optical spill surrounds each physical lens; vents, casing and unlit dial faces contribute zero. Base geometry and lamp contribution use identical coordinates, without per-lamp offsets. The shader adds light RGB multiplied by this scalar and its animated intensity to the ambient-lit base. Turning illumination off preserves the photographed fixtures. Source contribution PNGs are opaque grayscale for inspection; export copies their weight into linear alpha so the runtime texture's sRGB conversion cannot alter it.

The baker also subdivides the four bridge sections into eight square base/contribution pairs and the dashboard into three. Each texture is 1024 × 1024, with original-density pixels, padding and a two-pixel neighboring guard band. Narrow joins between generated quadrants are blended identically in base and contribution during preparation. [lighting-tiles.json](lighting-tiles.json) records the source regions and texture interiors. The mesh sections keep their fixed dimensions; shared sampling in [light-textures.ts](../light-textures.ts) maps each pair onto the same original UV domain. Square tiling does not increase source detail or assume a performance gain on every GPU. Transparent source RGB is removed during export to keep window cutouts clean.

Earlier panoramas, cube reprojections, generated planet studies, projected plates and the Boolean model in [cockpit.blend](cockpit.blend) remain visual provenance.

Earth uses NASA imagery: Blue Marble Next Generation by Reto Stöckli (July 2004 surface), the Blue Marble cloud composite (2002 release), and Black Marble VIIRS night lights (2016). [Source URLs, credits and checksums](earth/sources.json) accompany the prepared maps; usage follows [NASA's media guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/). [cockpit_earth.py](../../../../../tools/assets/cockpit_earth.py) downloads originals into the ignored build cache and prepares 8K/4K surface and cloud maps plus 4K/2K night lights. [Prepared checksums](earth/prepared.json) record the outputs. Normal builds use these local derivatives without downloading from NASA. The demo uses the lighter 4K surface/cloud pair and 2K night lights; set `EARTH_QUALITY` in the scene builder to `8k` before rebuilding for a higher-detail export. Cloud coverage occupies the surface texture's unused alpha channel while retaining independent animation coordinates.

The distant sky uses [Hipparcos positions and photometry](stars/source.json) (ESA 1997, distributed by CDS), prepared by [cockpit_stars.py](../../../../../tools/assets/cockpit_stars.py). [starfield.py](starfield.py) builds one mesh of tiny steady points, with restrained exposure and colour variation. The catalogue is stored locally; there is no sky texture download or animated twinkle.

From the repository root, using the pinned Blender installation:

```sh
# Only when regenerating the Earth derivatives:
blender -b --factory-startup --python-exit-code 1 --python tools/assets/cockpit_earth.py
blender -b --factory-startup --python-exit-code 1 --python examples/demos/scenes/cockpit/authoring/project_cockpit.py
python tools/ipp.py build demos-cockpit-native-assets demos-cockpit-assets
```

The builder also runs through Blender MCP with `runpy.run_path(...)["build"]()`. Preserve unrelated unsaved scenes first. Regenerate after changing sources, geometry or mounts. [export_projected.py](export_projected.py) uses the standard scene exporter and publishes square RGBA base and scalar contribution inputs consumed by the app-owned shaders. Runtime metadata accompanies both target-correct asset products. The authoring scripts and runtime types own the detailed dimensions and material inputs.
