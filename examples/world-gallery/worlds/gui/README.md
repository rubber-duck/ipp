# GUI Demo

This gallery world mounts a real `@ipp/react/gui` application on one translucent 3D Surface, projected from a textured metal cube along the shared normal of its recessed lens and the panel. An authored open frustum carries a view-dependent volumetric shader with sparse drifting dust and faint projection rays; a soft gray studio backdrop, ambient metal fill, and an upright baked base and tiled floor provide fixed illumination without relighting the moving projection. Core layout, paint, hit testing, focus, text editing, control values and scrolling own the interaction semantics; React receives committed callbacks to update the explanatory sidebar and the surrounding scene.

The GUI demo uses retained controls and shared font glyphs in all three skins. Panel frames, slider ticks, control surfaces, rounded borders and glow use parameterized boxes. PULSE fills with a radial gradient centred on its icon, and Neon adds resting halos around the controls. SPAN resizes the header frame while its corner radii, border and gradient keep their authored metres. UPLINK stays disabled while SCAN runs and transitions through the skin's disabled lane. Cube, signal, pulse and skin icons come from the bundled Shure Tech Mono Nerd Font; each sits in a fixed cell whose own alignment centres the glyph, and decorations are offset by leading Stack margins. The scrolling sine trace, independent pulse and reference grid use immutable Surface curve assets. Only the two trace nodes move; gain changes their scale without rewriting their geometry. Skin selection changes material values while preserving node identities, focus, control values and animation controllers.

Signal gain changes the projector light, cube energy and waveform amplitude. Autoscan scrolls two sine cycles through the stationary graph. PULSE adds an independent bright pulse with a flat baseline, including while scanning is paused. The Host owns both animation clocks and the separate 3D dust phase. [dashboard.tsx](dashboard.tsx) composes the panel, [presentation.tsx](presentation.tsx) owns the shape/icon helpers and verified glyph choices, and [waveform.tsx](waveform.tsx) owns curve placement and acknowledged animation bindings. [scene.tsx](scene.tsx) coordinates readiness, [projector.tsx](projector.tsx) supplies the 3D assembly, and [controls.tsx](controls.tsx) exposes the committed state in the sidebar.

The gallery build exports the packed [Blender projector](authoring/PROVENANCE.md) without rebaking and uses the [shared font](../../../../assets/fonts/README.md). Control geometry is authored directly in the application; the build converts the three waveform SVG assets through the shared Surface converter.

The GUI demo intentionally keeps the complete maintained font: 11,307 glyphs and 11,306 mapped code points in the 2,336,172-byte source, producing the 9,126,548-byte transport fixture. Its callsign editor accepts user text beyond the labels currently on screen, and the SIL Open Font License requires a subset to remain a properly attributed modified font under a non-reserved name. Reducing the asset to current static labels would silently narrow editable-text coverage, so startup work must improve transport and preparation without shrinking this large-font fixture. A future subset would need an explicit supported character repertoire, generated attribution and editable-text coverage tests.

Gestures that start on the panel operate the GUI; pointer and wheel input outside the panel controls the gallery camera. Each gesture keeps its initial owner across panel boundaries. Use Reset camera to restore the authored view. See the [gallery guide](../../README.md) for building and validating the world.

Use **Isolate GUI panel only** in the scene controls to unmount the projector, floor, backdrop, lights and beam while retaining the GUI Surface and camera. The FPS readout stays visible; compare it at the same camera angle after the rate settles, then use **Restore full scene** to remount the assembly. The isolated view still includes GUI text, backgrounds, controls and waveform animation, so it measures the complete Surface workload rather than a single rendering primitive.
