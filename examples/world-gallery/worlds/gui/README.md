# GUI Demo

This gallery world mounts a real `@ipp/react/gui` application on one translucent 3D Surface, projected from a textured metal cube along the shared normal of its recessed lens and the panel. An authored open frustum carries a view-dependent volumetric shader with sparse drifting dust and faint projection rays; a soft gray studio backdrop, ambient metal fill, and an upright baked base and tiled floor provide fixed illumination without relighting the moving projection. Core layout, paint, hit testing, focus, text editing, control values and scrolling own the interaction semantics; React receives committed callbacks to update the explanatory sidebar and the surrounding scene.

The GUI demo combines an outlined pulse control, a pill-shaped autoscan checkbox, a ring-thumb gain slider, callsign editor, framed telemetry scroll view and two in-world skins. Vector drawings supply the panel corners, waveform, borders and control shapes through ordinary GUI skin parts; Aurora and Ember change the pulse silhouette while preserving control identity. The dark panel fills carry alpha 0.9, while text and thin control outlines remain crisp. Signal gain changes the projector light, cube energy and waveform amplitude. Autoscan scrolls a smooth sine wave from right to left inside its stationary GUI grid. PULSE adds an independent bright pulse traveling in the same direction, joined to a flat baseline on both sides. Both traces remain visible together, and PULSE also works while scanning is paused. Host-owned animations drive both traces, a separate looping Host phase drives the 3D dust, and skin selection recolors the complete projection assembly. Each button skin also supplies complete color, opacity and scale animation tracks for every interactive state, so the runtime can transition the paint without replacing control identity or values.

The gallery build converts the maintained [GUI mark](authoring/svg/gui-mark.svg) and dashboard drawings from `authoring/svg`, exports the packed [Blender projector](authoring/PROVENANCE.md) without rebaking, and uses the [shared Shure Tech Mono Nerd Font](../../../../assets/fonts/README.md) from `target/font-assets`. The runtime loads converted drawings and projector assets from `target/gallery-gui-assets`; editable SVG sources stay with the authoring files. [scene.tsx](scene.tsx) owns readiness and runtime-created clips; [dashboard.tsx](dashboard.tsx) composes the GUI and its skins; [waveform.tsx](waveform.tsx) binds acknowledged curve nodes to Host-owned motion; [projector.tsx](projector.tsx) owns the scene assembly and Host animation bindings; [controls.tsx](controls.tsx) is a read-only DOM explanation and committed-state readout.

The GUI demo intentionally keeps the complete maintained font: 11,307 glyphs and 11,306 mapped code points in the 2,336,172-byte source, producing the 9,126,548-byte transport fixture. Its callsign editor accepts user text beyond the labels currently on screen, and the SIL Open Font License requires a subset to remain a properly attributed modified font under a non-reserved name. Reducing the asset to current static labels would silently narrow editable-text coverage, so startup work must improve transport and preparation without shrinking this large-font fixture. A future subset would need an explicit supported character repertoire, generated attribution and editable-text coverage tests.

Gestures that start on the panel operate the GUI; pointer and wheel input outside the panel controls the gallery camera. Each gesture keeps its initial owner across panel boundaries. Use Reset camera to restore the authored view. See the [gallery guide](../../README.md) for building and validating the world.

Use **Show vector panel only** in the scene controls to unmount the projector, floor, backdrop, lights and beam while retaining the vector GUI Surface and camera. The FPS readout stays visible; compare it at the same camera angle after the rate settles, then use **Restore full scene** to remount the assembly. The isolated view still includes GUI text, backgrounds, controls and waveform animation, so it measures the complete Surface workload rather than drawing tessellation alone.
