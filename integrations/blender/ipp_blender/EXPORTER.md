# Blender extraction

[`export_scene`](exporter/scene.py) runs synchronously on Blender's main thread. The callback receives immutable bytes and a content type and returns an immutable source URL. The result contains ordinary JSON-compatible values, with no retained Blender references. The server owns revision/session lifetime and the browser adapter uses the target-generated SDK to create runtime entities and encode animation JSON.

Live and disk exports use opaque session/revision/asset names. The URL does not encode a content hash. The asset store may privately reuse unchanged detached recipes or completed payloads across revisions; a restarted export session cannot reuse their names for different content.

## Scene identity and coordinates

[Identity and transform extraction](exporter/identity.py) reads the current visible, render-enabled scene and includes required object ancestors as transform entities. Ordinary object parenting exports stable producer parent references and local transforms, including Blender’s parent inverse. Empty objects are supported. Bone parenting exports `parent` and `parent_bone`, using the parent skeleton's stable joint ordering and child TRS relative to the evaluated bone head frame (including Blender's tail offset and parent inverse). Runtime hierarchy follows the animated joint directly; no duplicate attachment animation is baked. Vertex parenting is baked into the current world transform with a diagnostic. An invalid ancestor omits dependent children rather than leaving dangling references. `ipp_id` object custom properties provide stable producer identities; missing identities are assigned UUIDs and duplicate local identities are repaired with a diagnostic. Meshes with multiple material slots retain an object transform entity; their geometry splits into identity-transform children whose IDs append `:material:<slot>` and whose names append ` [material <slot>]`. Ordinary entity names preserve the Blender object name exactly; renames leave `ipp_id` unchanged. Linked objects without a usable local identity, unsupported object types and unrepresentable content produce diagnostics.

Blender coordinates become runtime coordinates through `(x, y, z) → (x, z, -y)`, multiplied by the scene unit scale. Mesh normals and bone spaces use the same basis. Camera/light local axes retain their local negative-Z viewing direction. Object-local and joint-local matrices must decompose into finite positive-scale TRS without shear. Hierarchy composition retains world-space shear from nonuniformly scaled parents. Camera extraction supports symmetric perspective and orthographic projections and uses Blender's render dimensions/pixel aspect to obtain the vertical projection.

## Meshes, skinning and shape keys

[Mesh and rig extraction](exporter/mesh.py) uses evaluated geometry for rigid meshes, so enabled modifiers are baked into the snapshot. Triangles expand to independent corners to preserve UV and hard-normal seams. Skinned meshes use the original undeformed mesh with exactly one linear vertex-group armature modifier. The exporter sends bone rest transforms, evaluated local poses, and mesh-specific inverse binds; it never exports the armature-deformed mesh together with a skin operation. Every weighted vertex needs one to four influences and rigs have at most 32 parent-ordered bones. Additional modifiers, preserve-volume skinning, envelopes, unsupported shape-key combinations, local shear and unsupported rigs are rejected with diagnostics. Constraints reflected in evaluated joint poses are baked into those poses.

A mesh with exactly one relative shape key plus Basis exports Basis as `mesh.source`, the key as `mesh_pose.source`, and its current value as `mesh_pose.weight`. The endpoints use the same expanded triangle corners and indices, including material splits and seams; target positions/normals are read through the basis triangulation. UVs and materials belong to Basis. Mesh extraction uses temporary copies and never changes authored key values. This pairwise runtime mapping requires a Basis-relative key, no vertex-group mask, no enabled modifiers except one supported linear armature, no isolated-key display, and a finite weight in `[0, 1]`. Muting the key yields weight zero. Absolute keys, multiple targets, out-of-range weights and unsupported rigid combinations retain the existing evaluated-mesh snapshot export with a diagnostic, without runtime mesh-pose animation. For skinned meshes, both endpoints are extracted before armature evaluation; the base retains joint indices/weights and the target supplies positions/normals. The runtime interpolates the endpoints, then skins the result using the independently animated skeleton. Unsupported active shape deformation with skin is rejected; unsupported zero-valued keys retain the existing skinned snapshot with a diagnostic. Shape-key endpoint edits publish new immutable target bytes while weight edits retain both sources.

## Materials and lighting

[Appearance extraction](exporter/appearance.py) supports opaque Principled base color/metallic/roughness factors or a direct base-color image using the active UV layer. Material custom property `ipp_unlit` requests an unlit factor or texture material. Textured Principled surfaces retain PBR lighting with constant metallic and roughness factors. The image must be a single byte sRGB RGB/RGBA image with opaque pixels. Images retain their authored dimensions; runtime device capabilities determine whether they can be rendered. IPPT RGBA rows and mesh V coordinates both flip to the runtime's top-left convention. The current runtime texture sampler determines filtering; Blender sampler-node settings are not represented.

[Camera and light extraction](exporter/view.py) maps directional, point and spot lights to the runtime light kinds. Area lights are unsupported. The light-data custom property `ipp_intensity` gives an explicit runtime intensity and `ipp_range` gives a range in runtime units, defaulting to 20. Otherwise Blender energy is approximated as directional intensity or `energy / (4π)` for local lights, with a diagnostic. Only spotlights request runtime shadows. Light-data `ipp_shadow_near` (positive, below range) and `ipp_shadow_bias` (nonnegative normalized depth) override the default near plane and bias. Place the near plane before the closest caster and keep bias small enough to preserve contact shadows; perspective depth makes the same bias displace shadows farther from distant lights. Their Blender radius (`shadow_soft_size`) exports as `Light.shadow_radius` for contact-softening; spot blend continues to control beam falloff independently. This mapping is an authoring approximation rather than photometric equivalence with Blender.

World ambient lighting exports constant active Background color multiplied by Strength as scene `ambient_light` linear RGB. A non-node World uses its color at unit strength; no World exports zero. Unsupported World shader graphs or volume shaders emit `world-unsupported` and export zero, clearing stale fill. This is uniform ambient fill, not an environment-map or Blender render equivalence.

## Actions and reusable clips

[Active actions](animation.py) are sampled into scalar local-transform tracks, quaternion rotation tracks and full joint-local pose tracks. Sampling uses the scene FPS across the complete active action frame range, with evenly spaced samples no more than one frame apart and both endpoints. Curves become sampled linear runtime interpolation. Animation descriptions use JSON, allowing the receiving target's generated SDK to encode its binary animation contract. Object and shape-key action players start paused and loop; baked particle playback is described below. The exporter restores the original frame and subframe in a `finally` block.

The `clips` catalog also exports active and stashed NLA actions independently, with action name, target, slot-qualified identity and immutable clip source. NLA strips establish action/slot ownership; unrelated global actions are never guessed onto rigs. Library sampling ignores strip blending/timing and mutes NLA temporarily, then restores the original action, slot, mute state, pose bases and frame/subframe even on failure. Active playback remains in `animations`; library entries do not create extra players. Active shape-key actions appear in both collections, so clips-only disk import retains their animation. A reusable catalog of inactive shape-key actions is not yet exported.

Parent actions animate their exported transform once and runtime hierarchy propagates the result to descendants. A supported shape-key active action produces a `MeshPose.weight` track for each material part, with the same FPS/sample bounds. [Shape-key sampling](mesh_animation.py) shares timeline evaluations for matching ranges and detached samples for shared datablocks while retaining every target association. Shape-key drivers and active NLA composition are diagnosed rather than exported as weight animation. Animated topology/materials/camera parameters and general driver/constraint graphs are not converted into runtime operations. The current snapshot captures their evaluated values where supported.

[Active light-data actions](light_animation.py) export sampled `Light.intensity` and RGB tracks, with reusable clip associations. Intensity follows the static light conversion: animated `ipp_intensity` takes precedence over energy; without it, Sun energy maps directly and Point/Spot energy divides by `4π`. Sampling restores the frame and subframe on success or failure. Inactive light NLA actions, active NLA composition, drivers, and other animated light parameters are outside this subset. Unsupported drivers or active NLA composition produce a `light-animation-unsupported` diagnostic.

## Limits and validation

Extraction has no object-count, texture-resolution, animation-sample, payload-size, snapshot-size, or aggregate-storage quota. The current runtime [mesh format](../../../crates/ipp-core/src/services/asset_management/MESH_FORMAT.md) still requires at most 65,536 expanded corners per mesh, and skeletons support at most 32 joints; [assets.py](assets.py) owns the emitted binary encodings. The viewer registers encoded animations over the asset data plane, independently of World command buffers and their limits. Network reads use bounded chunks and pending-update queues apply backpressure without limiting total scene or asset size. Allocation and storage failures remain observable. A rejected armature cannot leave a skin referencing an omitted skeleton.

Run the focused numerical checks with the installed Blender:

```sh
blender --background --factory-startup --python-exit-code 17 --python tests/blender/exporter_check.py
```

The [numerical check](../../../tests/blender/exporter_check.py) reconstructs emitted geometry independently and compares it with Blender's evaluated result, including hierarchy and combined shape-key/skinning behavior. It also verifies identity, restoration and unsupported-data handling. Evidence is written to `target/integration-artifacts/blender-export/checks.json`. Run `python tools/ipp.py test blender` for the complementary real transport and completed-frame harness; see the [development guide](../../../docs/development/blender.md).

## Particle systems

[Blender emitter systems](particles.py) export as separate effect entities. Set the emitter object's custom property `ipp_particles` to `NATIVE` (default) or `BAKED`. Native recipes support static face emission, Newtonian velocity, lifetime/size randomness and gravity; seeded distributions are IPP's own, so use baked mode when Blender's exact sampled motion matters. Unsupported force fields, collisions, children, moving emitters and rotation settings emit `particle-unsupported` diagnostics with the baked alternative.

Baked mode sequentially samples the scene frame interval at its FPS, including simulation warmup, into immutable IPPC data. Stable Blender particle indices become particle identities. Locations, velocities and quaternions are converted to IPP coordinates, and an ordinary property clip drives `ParticlePlayback.time`. That clip is also exported in the reusable clip library, so clips-only disk imports can bind playback without reconstructing it. Disabled Blender particle rotations export identity quaternions rather than unspecified internal rotation data. Sampling restores the original frame and subframe even on failure. The cache is portable interchange data, not Blender's internal point-cache representation.

HALO rendering maps to ParticleSprite using the selected material’s supported base color (white without a material). Set particle-settings custom property `ipp_blend` to `ALPHA` (default) or `ADDITIVE`; OBJECT rendering maps a single static instance mesh and its supported material to ParticleMesh. Hair, collections, trails and Geometry Nodes particle translation are outside this exporter. The source remains an independent scene entity; disabling Blender’s Show Emitter for rendering omits its visible mesh while preserving its transform and particle effects. The receiving runtime must include `particles`; the adapter reports a missing capability explicitly.

Use `blender -b SCENE.blend --python-exit-code 1 --python tests/blender/particle_bake_check.py -- EXPORT_DIRECTORY` to compare every baked sample in a standard disk export with a fresh Blender simulation. This includes identities, lifetimes, positions, velocities, rotations, sizes, reusable playback associations and associated light-data samples.

## Shared sampling and bounded delivery

Compatible active transforms, rigs, light properties, shape keys and baked particle systems register sample jobs with [`SamplingSchedule`](sampling.py). The schedule evaluates each required frame once across jobs and captures detached values before advancing. Jobs retain one next-frame entry; sampled data still preserves every authored sample. Shape-key datablocks share their captured values across instances. Particle jobs include sequential warmup. When particles are baked, fractional action ranges use a separate merged pass because subframe evaluations change Blender simulation integration. Alternate action/NLA bindings retain isolated sampling and restoration. Every exit restores the authoring frame and subframe.

The browser adapter generates commands lazily through [`ordered-batches.ts`](../client/ordered-batches.ts), using the shared client writer with pages capped at 256 commands and 128 KiB, including framing. Buffers also respect the protocol byte limit and share a Host-issued logical batch ID until the explicit terminator. IPP withholds evaluation and unrelated commands during that batch; a two-second Host-time deadline rejects stalled batches without rollback. The Host retains aliases across pipelined pages; failures retain prior committed effects. Export streaming bounds unacknowledged entity/clip groups independently of these runtime command frames. Full scene snapshots and immutable resources still scale with scene content.

The streamed exporter reserves names with [`AssetPlan`](asset_plan.py), assembles references, then closes the entity batch before producing detached geometry recipes, textures and sampled animations. [`AssetStore`](asset_store.py) owns the pending/ready/failed index. A pending HTTPS read returns 202 with its source and a same-origin WSS monitor URL. Readers subscribe by immutable name, receive its current state and subsequent terminal state, then fetch ordinary complete bytes. Monitor sessions fence producer restarts; failed production returns an explicit failure. Notifications carry availability only, never asset bytes or World commands. Unused declarations are settled as unavailable at export completion.
