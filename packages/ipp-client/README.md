# IPP client

`@ipp/client` supplies shared session and transport support for target-generated IPP clients. Applications author state and observe outcomes; the Host owns runtime clocks, evaluation and presentation.

## Build and connect

Use a generated client matching the Host's actual target. Native and WASM layouts are not interchangeable. Generated contracts and assembled distributions are build artifacts; maintain shared support here and generation in [ipp-schema-gen](../../tools/ipp-schema-gen/README.md).

Build the matching [headless example](../../examples/headless-client/README.md) from the repository root:

```sh
python tools/ipp.py dev headless-client --build
```

For browser use, serve a complete assembled distribution with its generated module, worker and WASM. The [gallery](../../examples/world-gallery/README.md) provides a working entry point; the [build guide](../../docs/development/building.md) covers prerequisites. Connection factories read the Host's announcement before returning and refuse a Host whose wire revision or compatibility hash differs from the contract the client was generated from: the connection attempt rejects with `HostContractMismatchError`, which names both hashes, and nothing further is sent on that connection. The Host itself checks no claim and [validates every operation](../../docs/architecture/protocol-and-schema.md#build-compatibility). A client without a generated SDK, such as an agent inspecting the protocol, opens a connection with `readHostContract(transport)` to read the announcement and pull the Host's binary contract, the bytes the generator consumes; the [schema-independent reader](src/host-contract.ts) documents the exchange. The [public source entry](src/index.ts) and [client interfaces](src/client.ts) define transport, diagnostic and authoring APIs.

`IppHostClient.datasets` exposes [typed Host-wide sources](src/datasets.ts) through a connection-owned lane. Updates preserve ordered successful deltas on a domain failure; transfer credit is separate from their one final outcome. Bounded source reads observe retained rows without acquiring streaming demand, and each page is independent. Producer release, explicit source destruction and connection cleanup follow the [data lifetime contract](../../docs/architecture/data.md).

Generated modules expose `ExpressionBuilder`, `encodeExpression`, `encodeDataWindows` and `encodeExpressionDriverInputs` using metadata exported by the actual Rust target. Upload expression bytes as an immutable expression asset through `registerAsset`, then reference it from a binding's asset-valued dynamic property. An optional `foo_parameter` remains an ordinary typed dynamic property, writable by protocol, drivers and AnimationController. A projection declares raw inputs as `column:<raw name>` and the optional input as `parameter`; use explicit fallback for absent or invalid inputs.

```ts
const expression = new ExpressionBuilder();
const row = expression.input("column:temperature", "f32");
const parameter = expression.input("parameter", "f32");
const scale = expression.fallback(parameter, expression.constant({ kind: "f32", value: 1 }));
const bytes = expression.encode(expression.binary("multiply", row, scale));
```

`host.datasets.bindingView(client.session, entity, { offset, limit })` returns a bounded completed page with exact kinds, explicit invalid results, stable row identities, source/binding incarnations, evaluated tick, availability and dirty. `driverStatus` observes expression driver availability and its last evaluation result. Both preserve dirty; successive pages are independent observations. Component inspection exposes `propertyDescriptors` beside named values for lifetime-scoped dynamic driver addresses. After removal/retyping or component replacement, inspect and reauthor against the new descriptor rather than reusing a departed address. [Combined maintained scenarios](../../tests/integration/scenarios/data-authoring.ts) show these APIs across real native and worker hosts.

`host.assets` reads authorized originals and exports explicitly selected working representations through the same connection-owned bulk reader used by captures and saves. `find(source)` returns a capability and supported formats only when Host policy grants access; a source URI alone grants none. `readAll(capability, { representation: "cpu", format: "texture-v3" })` returns reloadable encoded bytes, while `read(...)` returns a descriptor for streaming through `host.reads.chunks(...)`. GPU texture export performs asynchronous staged readback; unavailable representations and unsupported formats reject explicitly. Revoking a capability cancels its unfinished operations, while already published typed output remains detached. The [asset API](src/asset-exports.ts) describes cancellation scope, and the [asset architecture](../../docs/architecture/assets.md#client-read-authority-and-output-lifetime) owns authorization and lifetimes.

## Sessions and outcomes

`IppClient` convenience connections create a temporary World with the named `selectedSystems` and own its Host connection. `IppHostClient` separates connection lifetime from World discovery, creation, sessions and destruction. Every World creation names its Systems; there is no default selection, and a creation without `selectedSystems` is refused with `WorldSelectionRequiredError` before anything is sent. `createWorld()` returns the descriptor and exact runtime reference before `openWorld(reference)` opens an independently fenced session. A connection can hold several sessions, including peers authoring the same World. Closing a client releases only that session; destroying an exact World is a separate operation. Ordinary Worlds outlive connections.

All sessions and Host requests of a connection share its flow control. While the Host throttles a connection, its requests, batch pages and commands wait in call order instead of failing: a WebSocket through TCP backpressure, a worker port through the ingress credit its worker grants and returns as the Host admits input ([transport](src/transport.ts)). A sender that ignores its credit fails only its own connection. Waiting is not a timeout: a request's reply deadline (`timeoutMs`) starts when it goes on the wire. Waiting messages stay in the client's own memory without a count limit; a worker port that returns no credit for 30 seconds while messages wait fails its connection loudly, like a receiver that acknowledges no delivery for 30 seconds.

Opening an authoring session never selects presentation. `bindOutput()` explicitly binds a Camera's current output, while `canvasOutput(world)` names the canvas of a World that selects the Canvas System without a binding; `resolveOutput()` validates an existing exact token without following a replacement. Root output selection is separate from session ownership and is not a completed-presentation fence. Runtime World and output references are untrusted until the receiving Host validates their lifetimes.

Entity identities are World-local and can survive detach. Session-owned handles and pending work must not cross attachments; saved-World loads produce fresh runtime handles. Close declaration roots before closing their client. Worker connections own startup and teardown, including failure cleanup. [host-client.ts](src/host-client.ts) implements these connection boundaries.

Pending worker endpoints accept exact-connection closure while WASM is still loading, without opening a runtime connection or waiting for evaluation. A closed pending endpoint is removed before promotion; a ready envelope racing with close never sends the hello. Closing before `start()` still listens for the terminal close acknowledgement, and a closed transport cannot restart. Promoted endpoints retain normal ordered delivery acknowledgements and completion credit until their receiving endpoint is disposed. Endpoint closure does not stop a shared `WorkerHost` or its peers; the private `workerTransport` owner subsequently shuts down its own Host and cancels its outstanding startup fetch.

Every terminal client path retains `closure` and resolves `closed` with its reason, including idle remote detach and transport failure. This is a local session fence, not confirmation of World destruction, declaration cleanup or publication retirement. A definitely unsent detach can be retried; an unknown submitted outcome cannot. Convenience startup cancellation remains active through World creation and session opening and closes its owned Host connection.

Picking and projection require an explicit `view`: `root` validates the exact current output and expected viewport after ordered World evaluation; `publication` reads only the named retained CPU publication with explicit dimensions. Successful replies return the resolved descriptor, and picks carry World-qualified entity/component-incarnation and publication identities. Clearing a root never enables an implicit active-camera fallback. Historical CPU queries neither select presentation nor authorize routed input, and an unavailable publication fails rather than reading the latest one. Camera selection belongs to Host root binding; the protocol has no implicit active-camera activation, navigation or selection-notification lane.

Batches apply in order without rollback. Any entity reference (command targets, link placements and entity-valued fields) can name an entity by runtime handle, by a batch alias (`Entity.alias`) that an earlier command of the same batch created or adopted, or by symbolic id (`Entity.symbol(id)`). Aliases resolve in command order and behave exactly like the handle they name; a forward or failed alias rejects its command with `UnknownAlias`, and aliases never outlive their batch. A symbolic id resolves at its command's mutation boundary and rejects the command with `MissingSymbolicId` when no entity has it; the outcome's `symbols` reports each handle a symbol resolved to. One outcome reports at most 32,768 aliases and 32,768 symbol resolutions within one message; a batch that could exceed either, or whose alias, symbol and adoption reports could exceed the message, is refused before any of it applies. `Entity.create(alias, metadata, { adopt: true })` binds the alias to a live entity that already carries `metadata.symbolicId` instead of failing, and `insertComponent` with `adopt: true` writes only the listed fields of an existing component in place, keeping its incarnation; without a match both create or insert as usual. `Entity.setFieldIf(entity, component, field, expected)` is compare-and-set: it writes only while the stored field equals `expected` and otherwise rejects with `ValueMismatch` without effect. A semantic failure returns its scope and surviving identities; earlier effects remain. Keep returned identities for cleanup or correction. Transport failure is not proof that nothing committed. See the [outcome types](src/types.ts) and [mutation contract](../../docs/architecture/runtime.md#mutation-and-evaluation-boundaries).

Batch `effects` journal attachment writes, conditional detach results and adoptions with their original operation indices, including after later failure. An adopting operation that found its target reports an `adopted` effect; one that created or inserted reports nothing. Narrow on `kind` before reading an attachment effect's `receipt`. Each receipt identifies the exact parent World, anchor/component incarnation, producer revision and child; its `id` belongs only to the issuing session. Submit `{ kind: "detachWorldAttachment", receipt: id }` in an ordinary batch to detach only that acknowledged write, never a replacement. `attachmentRetirement(id)` distinguishes pending from retired publication/reservation ownership; a batch acknowledgement or arbitrary frame does not establish retirement. Keep the receipt until the required retirement is observed, then call `releaseAttachmentReceipt(id)`. Released and foreign handles fail at the operation boundary without erasing earlier effects. Closing the session revokes its receipt handles, not independently living Worlds.

`batch()` pages large edits through the shared [command writer](src/command-pages.ts) under a batch identity from a wrapping u32 counter shared by the connection's sessions, sends every page at once, and resolves with the whole batch's outcome from the reply to its final page. Earlier pages are uncorrelated and produce no reply. `openBatch()` returns a writer for producers whose batch spans several writes: full pages leave as they fill, and `finish()` sends the final page. The Host applies the batch as a whole when the final page arrives, so no page is observable before then and the World keeps evaluating while a batch is open. The Host's two-second batch deadline starts when the Host accepts a page of the batch and restarts with each later page; it runs only while the Host reads the connection, so pages waiting in flow control behind earlier input, including other sessions' input on the same connection, do not consume it. If the next page does not arrive in time, the Host drops the buffered pages, `onBatchAborted()` reports the failure, and the final page, if sent later, is rejected with the same failure. A writer whose producer or encoding fails never sends its final page and applies nothing. See the [client methods](src/client.ts) for correlation.

A batch has exactly one outcome. `RequestNotSentError` and `RequestRejectedError` mean nothing of the batch applied; a failed outcome reports its failing operation by its global index, with the aliases and receipt effects applied before it. Any other failure, such as a lost final reply, leaves the outcome unknown; do not infer that nothing applied.

Acknowledgement, resource readiness and completed rendering are distinct. Clients observe Host progress without advancing time. Inspection pages are independent observations, not an atomic World snapshot. Neither a session tick nor a CPU query establishes presentation completion.

## Physical presentation

`host.setRootOutput(output, viewport)` returns a root configuration binding, not a rendered frame. Query `host.presentation.surface()` for the actual graphics context and its limits, then select one exact binding with `host.presentation.select(surface, binding)`. The acknowledged dimensions and device-pixel ratio are used exactly; oversized views fail rather than silently clamping. Other configured roots and authoring sessions remain independent of that physical surface. `host.presentation.resize(view, viewport)` resizes the selected view in one request: the Host rebinds the same output with the new viewport and selects the new binding, answering the new view, so no frame is drawn with nothing selected and the renderer keeps the output's retained images and batches. The previous binding and view become stale, and a failed resize leaves them current. A separate `setRootOutput` deselects the surface until the next `select`, so it suits a first selection or another output.

`host.presentation.frame(view)` and `capture(view)` await an actual successful selected draw and frame end. A valid empty scene succeeds; invalid-camera clears, unavailable outputs and headless Hosts do not. Returned stamps identify the view, source publication and sequence. `afterSequence` waits for a later draw, while `publication` constrains the current authorized source rather than requesting historical replay. Rebinds, explicit deselection, resize and context replacement invalidate pending waits. Compare-and-clear operations cannot erase newer selections or equal-value rebindings.

After awaiting a child action or authoring ACK, `host.presentation.frame(view, { afterOutputs: [childOutput] })` observes the next eligible completed evaluation of that exact output included in the selected draw. Inputs are snapshotted and deduplicated before sending; `sources` returns the admitted minimum ticks and actual included publication witnesses. This works for idle/callback-only actions and equivalent unchanged cached content without requiring repaint. It cannot follow replacement lifetimes or relabel stale cached pixels. The barrier is post-admission presentation, not necessarily the action's first visible frame or physical display scanout, and uses no client time advancement. Both request and reply must fit the existing bounded protocol message; pending waits retain their ordinary cancellation/expiry and reliable-output ownership. See the [renderer inclusion contract](../../crates/ipp-render-gl/README.md#output-inclusion).

Capture returns immutable top-left RGBA8 pixels stamped at draw completion. Captures, World saves and contract retrieval use the shared [bulk reader](src/bulk-reads.ts), whose bounded chunks progress independently of World evaluation. Full-prefix and EOF acknowledgement releases a completed read; explicit release, connection closure or severe Host memory pressure also end its lease. Ordinary age or cache eviction does not. Completed CPU snapshots retain their old stamps across later view changes and context loss; uncompleted waits do not. Semantic-fence validation failures release the read once its identity is known. Each connection has its own allowance of pending waits, retained captures and capture bytes, from which the Host-wide bounds are derived ([limits](../../crates/ipp-host-session/src/services/presentation.rs)); a request beyond them fails with `Capacity` without affecting other connections' allowances. Context recovery requires a fresh surface/view selection without reopening Worlds or resetting their clocks.

The package has three import paths. `@ipp/client` carries no diagnostic or testing member on the Host client type. `@ipp/client/diagnostics` ([diagnostics.ts](src/diagnostics.ts)) holds read-only observations that every build answers: `renderDiagnostics(host).statistics()` for renderer statistics, undefined when the connection presents nothing, and `lifecycleDiagnostics(client)` below. They are measurements, not capture metadata or readiness fences. `@ipp/client/testing` ([testing.ts](src/testing.ts)) holds controls that change runtime behaviour for internal tests: `presentationTesting(host)` for context loss simulation, glyph atlas limits, the Surface cache budget and exhaustive draw checks, and the native presentation test transport. Only an `instrumentation` build honours them; against any other build each control throws at the call. The native GLES test host uses its side channel only for statistics and those controls; its frames and pixels use the same Host protocol as the browser worker.

## Host connections and World files

Resources identify immutable content. Changed bytes require a new identity; releasing producer ownership preserves actual consumers. Pending resources do not prevent valid state changes, and ready draws can continue independently. The [asset architecture](../../docs/architecture/assets.md) defines retention and recovery. The Host keeps unused completed assets in a 64 MiB cache by default; the worker option `assetCacheBytes` overrides that target, and 0 evicts on release. HTTP providers may advertise pending immutable sources with a source availability channel; the [worker provider](src/resource-worker.ts) waits independently of transfer concurrency and resumes ordinary reads when production completes.

`registerAsset()` delivers a named immutable source through the separate [source data plane](src/asset-sources.ts); `createAsset()` allocates a fresh source name and returns its descriptor. Delivery uses bounded chunks and completes registration independently of World command batches. Observe resource events for decode and graphics readiness. `releaseAsset()` releases producer ownership. Asset payloads never enter the generated World command codec.

Generated Host clients expose save/load through [world-persistence-client.ts](src/world-persistence-client.ts). Files preserve stored component state, controller descriptions and each controller's applied contributions, excluding presentation selections. Saving preserves resource references without fetching, bundling or relocating bytes; applications publish durable assets separately.

Transfers pipeline a bounded window of ordered chunks, draining submitted requests before cleanup. `saveWorld(session)` captures the authored descendant graph at one mutation boundary, between whole batches. A peer session's closure does not cancel the capture.

`inspectWorldGraph(bytes)` previews graph-local identities and durable names without publishing Worlds. `loadWorld(bytes, { worldNames })` previews the same owned upload before applying the supplied map or rename callback, then returns `{ root, created }` with every fresh exact World reference. Metadata and binding journals use bounded pages. Opening sessions remains explicit; loaded Worlds have independent lifetimes and acknowledged Worlds outlive the connection.

Cancellation, expiry and disconnect destroy only that transfer's unacknowledged fresh Worlds, never descendants merely borrowed by another transfer. A late acknowledgement/cancellation failure exposes `WorldGraphLoadError.graph` and `pendingCleanup` rather than losing identities; retry cleanup against those exact references. Transport send exceptions have unknown effects and terminally fence the shared Host, unlike definitely-unsent local validation or queue rejection. Large capture and restore operations remain synchronous and can pause the Host.

## Exact lifecycle targets

`client.watchLifecycle(targets, listener)` watches exact entity generations, entity/component pairs or component field values in that client's World. The SDK byte-pages registration and baseline ACKs without a total target-count quota. Install application identity maps before calling: listeners activate synchronously upon each ACK, before the promise resolves, and later pages are not an atomic whole-set cut. The returned immutable baselines and applied sequence/tick cuts are membership observations, not completed World frames. Event envelopes use tick zero and do not advance `observedTick`.

Each registration owns fresh member generations; duplicate targets are independent users. `remove()` withdraws only that watch, dispatching already handed-off prefix records before its ACK and fencing future callbacks. A consumer disposing a ref must locally fence its callbacks before awaiting removal; the removal ACK is not an immediate disposal barrier. Readding a target never reuses a generation. `closed` distinguishes removal from session/connection closure. `LifecycleWatchStartError.partial` preserves acknowledged members after a later page failure for exact cleanup; it never claims unknown unacknowledged effects. Unknown submitted control failures synchronously fence the logical client; known non-submission is reusable.

`watch.removeMembers(ids)` removes a subset using original `baseline.member` identities, never current target resolution. Every supplied identity is validated against that group before any send. Duplicate and overlapping selections share exact in-flight work; acknowledged duplicates return their original cuts without retransmission. Work scales with the supplied subset, not all groups or members. Other members and independent users survive. Handed-off prefixes remain observable until each remove ACK, so disposed consumers must locally fence callbacks before awaiting. Subset removal does not dispose the group; `remove()` still withdraws the remainder, resolves `closed` and idempotently returns all removal cuts.

Subset runtime failures expose the public type `LifecycleWatchRemoveError` with frozen `cuts` and `unconfirmedMembers`, plus the original `cause`. Import `isLifecycleWatchRemoveError` from `@ipp/client` to narrow an unknown caught value; no public removal-error constructor is exported. Generated targets contain independent support modules, so constructor identity is not a recognition contract. The guard validates the error and identity/cut shapes without copying or changing the owned information; it is not a provenance or retry-safety check. Cuts include only validated acknowledgements for selected members, including previously acknowledged duplicates. Unconfirmed means no validated removal ACK, not that the member is certainly still active. A definitely unapplied failure can be retried; unknown submission or endpoint loss retains terminal fencing. Whole-group `remove()` preserves its existing error behavior and cumulative-cut retry semantics. Original baselines never change; member cleanup bookkeeping lives only with its group.

A value member selects `{ kind: "value", entity, component, fields }` with kinds `128`, where `fields` are ascending schema field offsets. Its baseline reports the component's lifetime, and the listener receives `kind: "value"` records (`LifecycleValueRecord`) with the evaluated `tick` and `values` in the target's field order, or `null` while the entity or component is absent. A value member reports the current value first, after its ACK, then one record for each frame in which the observed fields differ from the values it last reported, carrying the evaluated tick; absence is reported once. Several writes in one frame produce one record with the final value, whoever wrote it. Value records are state: an undelivered record is replaced by a newer value while delivery stays in tick order. Lifecycle records are never coalesced. This SDK supplies identity and value observations; consumers retain responsibility for their own handle publication and callback ownership.

Every Host answers `lifecycleDiagnostics(client).statistics(output)` from `@ipp/client/diagnostics`; generated clients have no public method for it. Pass the exact acknowledged endpoint from a watch baseline; absent, foreign and ended endpoints reject rather than returning zero samples. Work counts indexed candidates before kind/liveness filtering. Traffic counts cumulative successfully retained events and their full reserved bytes, not wire traffic or current queue occupancy. Saturated samples cannot establish exact deltas. Queries share ordinary session ordering and reliable reply accounting; their zero-tick replies do not advance `observedTick`.

Target events, value records and filter observations use the existing physical connection account through actual delivery completion; no separate record count bounds them, and none is dropped or coalesced to make room. Output exhaustion explicitly closes all sessions on only the congested connection, without vetoing healthy mutations or other connections. Unrelated transitions produce no target output; Core's sparse index still performs its constant-time lookup.

## Compact schema rows

Generated row types follow the executed target's component layout. `RowsInput<Row>` supplies a complete table's `nextSlot` and read-only live-slot map to `encodeRowsTable`; generated wrappers such as `GuiTheme.encodeParts` select the matching layout. Encoding preserves caller-assigned identities and sorts live rows without modifying inputs. It does not allocate slots or restore dead-slot history. A whole-table field write replaces the value under core lifecycle rules, rather than merging row lifetimes.

Use `rowPatchFields` or generated `patchPartsFields` for detached, layout-ordered `FieldWrite` values in ordinary component writes. Existing `patchParts` produces equivalent commands. Undefined entries are omitted; null clears only optional properties. No helper bypasses core slot-liveness or semantic validation. In particular, the same structural paint-row type is used by themes and skins, but core restricts skin overrides to base part keys. The GUI-only compiled `guiPaintPartIndex` helper provides the keys; row slots are separate caller-owned identities, not paint indices.

## Ordinary GUI controls

Control values, scroll state, eligibility and bounds are ordinary component fields: read them with ordinary component reads, change them with field writes or `Entity.setFieldIf`, and observe them through value watch members. GUI-enabled generated clients add the `Entity.guiAction(target, action)` command builder and read-only focus, pointer and active item queries: `inspectPage({ collection: "guiFocus" })`, `inspectPage({ collection: "guiPointers" })` and `inspectPage({ collection: "guiActiveItems" })` return the World's focused control, if any, one record per live pointer on a control and one record per group with an active item. `inspectPage({ collection: "guiPreferences" })` reads the World's GUI preferences, such as reduced motion, which `GuiPreferencesUpdateCommand` changes. An action target names the ordinary entity (by handle or `Entity.symbol`) and the control component incarnation. These calls belong to the client's World session and require no root binding, presentation surface or native input context.

A semantic action is an ordinary command: submit `Entity.guiAction(target, action)` with `client.batch` or in any batch, and the batch outcome is its result. It applies in batch order at its operation's mutation boundary, or stops the batch without effect with `StaleTarget` (the entity no longer holds that component incarnation), `Unavailable` (the control is disabled, hidden or unavailable), `UnsupportedAction` (the action does not fit the control) or `InvalidValue`. Value actions write the control's fields; observe them through value watch members. Press, submit and focus changes are published to effect subscribers with the tick of the batch's frame. Focus set by an action has no owning session: closing a session keeps it and any client may blur it. A lost batch reply is not proof of no mutation; do not automatically replay uncertain actions.

The former GuiRoot/node edit, input and observation SDK/wire operations are removed rather than translated. Declaration producers use ordinary component/link batches; physical input adapters have a separate service-owned context boundary.

`host.input.open(view)` acquires one exact physical presentation/input lifetime, independent of authoring sessions. Its `send` routes normalized pointer coordinates, logical wheel deltas, keys and blur through completed composed publications; routed commands still validate current paths, eligibility and control incarnations before mutation. Correlated outcomes include applied/rejected/cancelled counts and unconsumed wheel movement. They are not application callbacks or frame barriers. Closing or replacing the physical context cancels capture/native ownership without destroying Worlds.

`open(view, { blockers })` explicitly selects exact World/entity/PickingGeometry incarnations as input blockers; unmarked renderables remain transparent, and stale entries never retarget replaced shapes. Pointer down/up carry a primary, secondary or auxiliary button; only primary may activate a GUI control. Successful wheel replies retain the full or partial unconsumed movement after innermost-first ordered consumption. A scene gate may authorize a wholly unconsumed gesture once, never a rejected or cancelled one. Physical/native discriminants and nested layouts are part of the generated target compatibility hash, not a private byte subprotocol.

The physical context exposes authoritative `nativeText` and synchronous `onText` updates. `editText(fence, edit)` retains the exact World/entity/component incarnation and native edit generation for single-line editing, selection and provisional composition. An external write to the committed text resets the native record and advances its generation, invalidating old edits. Native replies/notifications carry no completed tick and do not advance a World clock. The Host reserves payload plus simultaneous framing storage on the existing physical connection account before copying native output; application effects retain their independent acknowledged observation path.

`subscribeGuiEffects(listener, options)` registers an independent observer on the client's exact World. Application effects (press and submit) are the default; feedback selects actual changed logical focus and explicitly commanded pointer feedback, not a complete focus/input stream. Value changes are not effects; observe them through value watch members. Pointer feedback describes that command's pointer state, not aggregate pointer state, and carries no pointer-lease authority. Applied effects retain their original entity/component lifetime, ancestry and source, including actions from another issuer and historical routed publications.

Registration returns an opaque subscription and a `start` ordered ACK marker. The listener exists before transmission and activation happens synchronously on ACK receipt, before the subscription promise resolves. Events immediately following that ACK can therefore run before the caller's `await` resumes. Declaration consumers need their live acknowledged-identity map ready for that window; registration does not atomically acknowledge declarations or replay history. `unsubscribe()` dispatches its already-retained prefix, then its ordered end marker fences later callbacks. `closed` reports unsubscribe or logical-session closure. Unknown submitted control failures fence that logical client; definitely unsent requests remain retryable.

Observation ordinals increase within each subscription, with gaps allowed. Their effect ticks and ordinals identify applied mutations, not completed frames; observation envelopes have tick zero and never change `observedTick`. Marker cuts have identity and FIFO meaning only, not numeric watermark or clock semantics. The Host uses one connection output account for correlated reservations, events, receipt replies, observation retention and peak encoding. Observation delivery transfers its existing lease into the ordinary outbox; socket handoffs retain Host-thread credit until actual flush completion. Worker delivery reserves the simultaneous Rust/JavaScript copies before copying and retains transferred-payload credit until exact transport acknowledgement or confirmed endpoint disposal, not merely borrowed-buffer invalidation. A slow observer fails its connection explicitly without vetoing healthy issuers or other observer connections.

`createWorkerHost()` owns one worker Host, clock and optional physical surface. Its independent `connect()` transports share that Host without sharing connection budgets or World-session lifetimes. `openPort()` transfers a receiving endpoint to another owner; dispose it only after closing that endpoint or stopping its receiving worker. Host shutdown requires disposal of transferred endpoints. `workerTransport()` remains a convenience owner of a private Host and one connection, using this same path. Connection and delivery identities never reuse an earlier ACK; closing/unresponsive endpoints retain bounded completion tickets until delivery or actual disposal. The [worker boundary](../../crates/ipp-wasm/README.md) defines ownership and teardown.

Native embedders consume `ReliableResponse`, not an unaccounted `Vec<u8>`. Splitting bytes for socket delivery also transfers a non-Send completion lease that stays on the Host thread. Dropping a response releases its allocation; the former unaccounted Host-wide response-buffer recycling API is removed. This boundary establishes bounded ownership, not an allocation or performance improvement.
