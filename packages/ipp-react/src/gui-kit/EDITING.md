# Editing and form controls

Import the components from `@ipp/react/gui-kit`. Mount them under `GuiKit` with the Cybertron or Glass skin. Each uses the active skin's existing text input, secondary action and text palette recipes. The [mounted editing specimen](../../../../tests/gui/agents/scenarios/editing.tsx) exercises these controls with both generated clients.

## Plain text and credentials

`Textarea` uses the native `GuiTextInput.text` field. It accepts plain LF-separated text. Set `rows` for the default height or `inputHeight` for an exact height in Canvas units. The renderer wraps at the available text width and reveals the active caret vertically. Up/Down follow measured lines. Home/End move to the endpoints of the current visual line, and Shift extends the selection. Ordinary Enter inserts LF. Ctrl/Command+Enter or an explicit `submit` action submits. Basic left-to-right font layout and grapheme boundaries follow the runtime's existing text contract. Selection, clipboard and IME use the native target and editing generation, including when an external controlled value replaces the text.

`PasswordInput` uses the same native field while its Show/Hide button changes presentation. `purpose` accepts `current-password` and `new-password`. `revealed` and `onRevealChange` control presentation independently of the text. `readOnly` permits focus and selection while refusing edits. `disabled` also disables the reveal button. The physical input bridge provides the password or one-time-code autocomplete hint on the actual focused buffer. The application may supply `textForm(target)` to its Canvas input adapter for opt-in association with an HTML form ID and field name. The buffer represents the currently focused field. Applications submitting complete forms should assemble values from their fields. Browser and third-party password manager behavior depends on the provider and requires manual verification with that provider. Semantic agent observations redact passwords and one-time codes regardless of their visual masking.

`OtpInput` has one focusable editing field and a row of visual positions. `length` is 1–64, and `characters` is a case-sensitive alphabet of printable ASCII characters, defaulting to digits. Insertion and paste filter other characters and fill the available slots while retaining unselected characters before and after the selection. `onComplete` fires when an observed edit fills a previously incomplete code. Clearing a position makes another completion possible. For all three controls, `value` means controlled synchronization and `defaultValue` seeds an uncontrolled field. Observing a value or submitting a form may expose sensitive text to application code.

## Labels and field messages

`useLabelTarget()` returns a control ref and its currently acknowledged handle. Pass the ref to a control and the handle to `<Label text="Destination" target={target}/>` or `<Field label="Destination" target={target}/>`. `activation` defaults to `focus`. Choose `press` or `toggle` for native action controls. Each action names the World, entity, component and incarnation. Replacing a nested target retires the previous association. A compound control explicitly selects its primary focus/action handle. Several labels may name that handle and are joined in tree order. Containers may nest and each label points only to its explicit target.

`Field` accepts `description`, `error`, `required`, `invalid` and `disabled`. A targetless Field renders visual content. A bound Field supplies semantic metadata for its own control in `createGuiAgent().snapshot()`. `TextField` and the three native text compositions bind their labels and messages automatically. These associations are available to the IPP semantic API. A platform accessibility tree requires a separate adapter.

## Application tokens

`TokenInput` accepts a `TokenDocument` consisting of `{kind:"text", text}` and `{kind:"token", id, label}` entries. IDs are nonempty and unique within a document. An empty label still represents an atomic token. Plain text is single-line, and pasted line breaks become spaces. Positions use extended graphemes for text and one unit per token. Pointer press places the caret at the nearest edge of a runtime-measured grapheme or token. A captured drag extends selection across cells. Arrows move, Shift extends, Home/End select a document endpoint, and Backspace/Delete remove whole units. The app receives normalized adjacent text runs through `onChange`; a controlled owner accepts a proposal by supplying it back as `value`. The exact mounted `GuiInputTarget` requires a connected application. Its client owns the caret and selection, and its adapter commits IME text only after native composition ends.

`serializeTokenDocument` exports a plain label projection and a versioned structured JSON document. Importing structured data requires the application's `acceptsToken` policy. Browsers forward the plain text and the optional `TOKEN_DOCUMENT_CLIPBOARD_TYPE` payload together from the paste gesture. Its plain projection must match. Plain clipboard text always stays text. Inserting an already-present token ID fails atomically. Supply an application clipboard with `write` and optionally `read`; a successful fenced write precedes cutting. The component never opens the OS clipboard on its own.

## File descriptors

`FileInput` accepts an application `GuiFileAdapter`. `choose(request)` returns ordered descriptors or `null` for cancellation. `subscribe(request, receive)` connects platform drop/paste support and may return cleanup. Each request has an `AbortSignal`. The GUI rejects late delivery and validates name, identifier, size, MIME match or file extension, maximum bytes and count. Set `maxFiles` to one for replacement or a larger bound for an accumulating list. A rejected replacement leaves the selection available. Unavailable chooser capability is visible. Application code owns each descriptor, byte buffer and derived asset, including cleanup when records are removed. IPP core receives presentation metadata only.

The browser `browserGuiFileAdapter({surface, picker})` from `@ipp/react/web` binds an explicit DOM zone for drops/pastes and, optionally, a visible `<input type="file">`. Supplying a picker provides a direct trusted-gesture path where browser policies refuse opening a dialog from an asynchronously delivered Canvas action. Descriptors include the original `File`. Native embedders implement the same adapter with their own chooser and capability policy. `onReject` reports per-file validation failures and `onError` reports platform failures.
