# Composing GUI behavior

The [GUI architecture](../../../../docs/architecture/gui.md) owns native interaction and authoritative state. This guide explains the kit's implementation seams for composing those capabilities without duplicating their owners.

## Composition boundaries

| Concern | Implementation and composition contract |
| --- | --- |
| Application selection | [Choice](choice.ts) observes native item selection and synchronizes controlled intent. Dropdown's [single-choice adapter](selection/dropdown.tsx) and [MultiSelect](selection/multi-select.tsx) keep application keys and declare selected rows; they do not maintain native active items. |
| Active-item navigation | Native [group membership](../../../../crates/ipp-core/src/world/systems/gui/local/composites/group.rs) and [group routing](../../../../crates/ipp-core/src/services/gui_input/router/group.rs) own eligible tree order, focus versus active-item movement, selected-item entry and activation. [OptionList](selection/option-list.tsx) and [Menu](overlays/menu.tsx) declare non-focusable Buttons in a Group. Their keyboard navigation needs the enclosing open overlay and its focused invoker or field; OptionList alone is not a standalone keyboard listbox. |
| Popup intent and dismissal | [useOverlayOpen and Floating](overlays/overlay.tsx) connect application intent to ordinary visibility fields. Native [overlay routing](../../../../crates/ipp-core/src/services/gui_input/router/overlay.rs) owns outside presses, Escape and modal blocking; [overlay state](../../../../crates/ipp-core/src/world/systems/gui/local/composites/overlay.rs) owns focus entry/return and invoker validation. |
| Value observation and controlled rejection | [ValueSynchronization](values/value-synchronization.ts) reconciles committed props with observed fields using exact-handle, compare-and-set writes. Subscription seeds and own-write echoes do not become public change callbacks. A controlled close or value rejection converges asynchronously after native input; composition must not pretend the native edit was cancelled. |
| Effects and lifetime | The [callback registry](../gui/callback-registry.ts) delivers committed effects through the root's ordered queue and fences session, declaration and control identity. Effect propagation follows the recorded ancestry; callback replacement does not recreate native entities. No local behavior should independently subscribe to raw input or retain another target registry. |
| Filtering and text | [SearchableDropdown](selection/searchable-dropdown.tsx) filters application options using observed native text. [Autocomplete](selection/autocomplete.tsx) composes text observation, suggestion acceptance and a semantic text write. Native editing, composition and focus remain in the text control. |
| Time and paint | Native GUI advances hint delays and repeats with Host time. AnimationSystem samples animation; skins and client compositions declare animation intent. Popup activation never schedules a timer, frame or animation sample. |

## Popup activation

[popupActivation](overlays/activation.ts) is an internal behavior used by Dropdown, SearchableDropdown, Autocomplete, Menu and MultiSelect. Its inputs are the existing overlay intent object, an application callback and whether activation closes the popup. Its output is a callback suitable for an already delivered native press. It owns no state, subscriptions, identities or cleanup.

The ordering is deliberate: read the overlay's live intent, discard activation while closed, request closing when configured, then call the application. The same overlay object exposes the updated intent immediately, so two queued presses before React renders produce one close and one application activation. A controlled owner may reject closing after that delivery; a later activation is then a new proposal. Reopening from an application callback also deliberately permits later activation. An omitted overlay supports a menu composed without popup management.

MultiSelect sets `closeOnActivate: false`: each delivered activation toggles application keys while the popup stays open. Closing remains the overlay's responsibility. Dropdown and SearchableDropdown use their selection adapter to omit a redundant selection callback when the already selected item is activated, while still closing. Autocomplete composes acceptance with the existing native text action and echo suppression.

Pass a single overlay intent object to the trigger, floating content and activation behavior. Recreate the callback during render so the reconciler publishes the current application callback after acknowledgement. Do not combine several owners that independently toggle or close the same popup for one effect. Native eligibility determines whether the press commits; this adapter does not retroactively cancel a committed effect based on changed option data. Removal, replacement, retained hiding and unmount stay under the reconciler's callback lifetime rules.

The maintained [selection tests](../../tests/gui-kit-selection.test.ts), [overlay tests](../../tests/gui-kit-overlays.test.ts) and [real input/rendering family](../../../../tests/gui/composites/README.md) cover these seams. Recording-World tests establish callback ordering and write scope; real transport and completed frames establish native behavior.

## UI SDK comparison

The comparison uses [UI SDK Core](https://ui-sdk.dev/docs/core) and `vercel-labs/ui` revision [`282f44729ce08282ef1dc37fa093b1997bbeb848`](https://github.com/vercel-labs/ui/tree/282f44729ce08282ef1dc37fa093b1997bbeb848/packages/core/src/foundation). Its useful lesson is to compose small policies with explicit inputs and outputs. IPP applies that at its existing native/client boundary.

Upstream [selection](https://github.com/vercel-labs/ui/blob/282f44729ce08282ef1dc37fa093b1997bbeb848/packages/core/src/foundation/selection/selection-model.ts) composes key-order and change callbacks; [popup creation](https://github.com/vercel-labs/ui/blob/282f44729ce08282ef1dc37fa093b1997bbeb848/packages/core/src/foundation/popups/create-popup.ts) composes presets and lifecycle. Its [focus recovery](https://github.com/vercel-labs/ui/blob/282f44729ce08282ef1dc37fa093b1997bbeb848/packages/core/src/foundation/focus/focus-recovery.ts) operates on DOM elements, and [typeahead](https://github.com/vercel-labs/ui/blob/282f44729ce08282ef1dc37fa093b1997bbeb848/packages/core/src/foundation/text/typeahead.ts) derives DOM labels and uses a client timer. These are reference implementations, not IPP runtime dependencies.

IPP does not currently compose typeahead into ordinary option lists or menus, nor open a closed dropdown on ArrowUp/ArrowDown. Ordinary control key routing and active-item mutation do not provide the same client contract as an exclusive client-managed input target. Application-side emulation would need a target-qualified input contract and a supported active-item operation; native group typeahead would need reviewed matching, timing and text-edit precedence. Those ownership decisions remain in existing Beads issues `ipp-l9yf`, `ipp-vss1` and `ipp-x787`; the activation behavior does not claim to implement them.
