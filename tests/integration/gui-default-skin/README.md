# Default GUI skin

This scenario shows that a control with no theme paints the runtime's default look in every static state and on every renderer. It declares each [skin-lab specimen](../../skin-lab/README.md) with its theme modules, which leave the controls on their default looks (the switch and amber variants name the [built-in looks](../../../crates/ipp-core/src/world/systems/gui/presentation/looks.rs) of the generated contract), and captures every state the specimen names through real physical input or semantic actions, each in its own temporary World.

```sh
python tools/ipp.py test gui-default-skin --egl-dir /lib64 --software
```

The worker case runs the shipped worker on WASM/WebGL in Chromium; the native case drives the GLES Host over WebSocket and its completed-presentation channel. Both run the same [scenario](scenario.ts) with the generated client of their runtime and the shared GUI font from the `font-assets` product; the page publishes that client before importing the scenario, so the specimens' sizes and colours come from the tokens of the runtime under test ([host-contract.ts](host-contract.ts)).

## Assertions

[Probes](probes.ts) read small logical regions of each specimen's composite capture and compare them with the [design language](../../skin-lab/README.md#design-language)'s colours and geometry rules, restated independently of the runtime's tables: interiors, idle, lit and disabled lines, the paired top-left and bottom-right cuts, the check mark, the switch block at either end, the slider value, rail thickness and thumb, a vertical slider's fill from the bottom, its thumb dragged up by real input, and bipolar fills between zero and the thumb on either side, a dial's cut housing, value arc, track, ticks and pointer in each state, dragged up by real input and filling a bipolar dial from zero, the caret and selection, label centring and the text inset, scroll tracks with their pointed tips and the thumb position at each offset, and Buttons as items: the selected fill under hover and focus, a selected and a non-focusable row, a field keeping focus while that row is pressed, and a row that Tab scrolls into view. Glow assertions compare a lit state with an unlit one in the same image. Every pinned input must reach its control and no feedback may outlive its state. Images and every probe result, passed or failed, are saved with the environment's evidence.

The scenario then declares the [panel-paints specimen](../../skin-lab/specimens/p01-panel-paints.tsx) with its band held still and probes its [custom paints](../../../crates/ipp-render-gl/src/services/render/CANVAS_PAINTS.md) ([paints.ts](paints.ts)): scanlines and a grid inside their panels and none on the page beside them, frames and glow equal to the plain panel's, a paint that does not compile failing its asset and leaving its panel the plain colour, a property write that moves the band, issues only a property write and leaves the other panels unchanged, and an ordinary clip on that property that sweeps the band once from where the write left it.

Last, the [overlap scene](overlap.tsx) puts default-skinned overlays over text painted before them: a dialog over labels, a toast over lines that cross its frame and buttons, a panel stacked on another panel's text, and a raised layer declared before the lines it covers. The renderer draws a run of GUI work as its shapes and then its glyphs and cuts the run where a later shape covers earlier text ([draw order](../../../crates/ipp-render-gl/src/services/render/gui_draw_order.rs)), so the scene must equal its twin with every overlay raised to a layer of its own, which never depends on that cut, and the opaque overlays must hide the text beneath them, which captures without the overlays and without the text show lies under and beside each one.

The probes check geometry and colour, not likeness to the AI-rendered sheets; the skin lab owns side-by-side comparison with the reference crops. Primitive kinds and asset demand are asserted by the core paint tests, and motion by the [gui-motion](../gui-motion/README.md) scenario and the core motion tests.
