# React GUI stress benchmark

The stress benchmark measures one GUI-enabled build at one source revision through a fixed React workload on real browser/WebGL or native/GLES paths, with separate timing, capture, work and allocation windows.

Run `IPP_BROWSER_ANGLE=vulkan ipp-browser-env python tools/ipp.py benchmark browser --scene gui-stress --repetitions 3` for the worker/WASM/WebGL path, or `ipp-browser-env python tools/ipp.py benchmark native --scene gui-stress --egl-dir /lib64 --repetitions 3` for the native GLES host and generated WebSocket client. Correctness runs through `python tools/ipp.py regression --only test:gui-stress:browser` and `IPP_EGL_LIBRARY_DIR=/lib64 python tools/ipp.py regression --only test:gui-stress:native`; `python tools/ipp.py test gui-stress` runs one repeat as the maintained correctness suite. Its strict build includes the actual stress scene and drivers without compiling unrelated examples.

## Workload

The [workload](../../examples/gui-stress/workload.ts) fixes seed, viewport/DPR, orthographic camera, assets, warmup, action order and independent panel-count and per-panel-tree-size sweeps: 1/4/9/16 panels at 16 explicit rows and 4 panels at 8/32/64/128 rows. Each logical panel contains layout, text, button, checkbox, slider, text input, image, drawing, scrollable explicit rows and a 10,000-item VirtualList; a separate cached raw Surface contributes drawing and text. Each repeat mounts a fresh React root and entities, resets the camera, verifies the initial list anchor/range, warms the scene, then runs six cycles of idle, one-subtree text edit, layout, theme, callback-only, semantic button press, checkbox toggle, virtual scroll, camera-only update, animation seek, cache-idle and keyed churn. The legal virtual-scroll targets stay distinct even at the optional 32-cycle maximum. The harness verifies logical panel and raw-Surface counts, semantic roles, observed effects, callback revision, control mutation, fresh list ranges, raw drawing regions and meaningful changed pixels. Skipped actions fail rather than reducing the workload.

After each acknowledged action, `frame(view, { afterOutputs })` requests Host-admission evaluation cuts for the exact root and child outputs and waits for a completed draw containing them. This measures post-admission draw completion including the barrier, not the first instant an action became visible. Correctness runs do not collect latency samples; those fields remain `null`, not zero. Capture publication/sequence identities remain distinct from World ticks. GUI traffic counts logical batches (one per client `batch()` call), the pages they occupy under the contract's page limits, and ordinary mutation operations in panel Worlds, while idle/callback-only zero-write and local-subtree bounds remain asserted. React writes one `SetField` per changed field, so the one-subtree text edit is one batch to the first panel's World with at most seven operations: the title text and the three color channels of the previously and newly highlighted row indicators. A toggle settles with the value it applied and is observed as the `checked` field; it publishes no effect. Whole-Host/all-child work diagnostics are required.

The diagnostics-enabled Host collector samples ordinary layout after each actual Host evaluation, independently of presentation. Per-World samples identify exact incarnations, ticks and evaluated/unavailable status; unselected layout and unavailable totals remain explicit. Host totals include unpresented Worlds and retained totals of retired lifetimes, without recounting cumulative work of unevaluated Worlds. This collector and its callback compile out without diagnostics; no component mirror or protocol publication is added. Correctness runs include a separate untimed probe for unpresented layout, retirement and missing capability on both graphics backends, outside the workload and its timing windows.

After each sweep's timed work and captures, the harness records the list's anchor fields and independently inspects direct-child `GuiVirtualItem` indices. A subsequent `afterOutputs` draw must include a later evaluation of that Canvas; reinspection must retain the same item identities/indices, and the control anchor must remain unchanged. The report retains exact World/list identity, item indices, inspection/inclusion/verification ticks and draw sequence. Bounds come from those observed declarations accepted by ordinary indexed layout, never from the requested/wanted range. Empty, discontinuous, missing or changing observations fail; the observation fence and inspection work stay outside timing/capture-work windows.

## Report

`gui-stress-report.json` identifies source revision/diff, workload hash, target contract/runtime/asset hashes, backend, machine, browser and graphics device. Each sweep retains initial/final completed-frame PNGs and per-action distributions of in-page update-to-acknowledgement and update-to-completed-frame latencies. Timed steps call `presentation.frame()` after each acknowledged action using the causal output cuts described above; no PNG encoding, `readPixels` or per-frame capture enters those windows. Correctness/statistics captures run before and after them. The semantic control-press latency includes action, press callback and frame; it is separately labelled and must not be mixed with authoring-update latency. Timings include React, generated client, transport and runtime scheduling; they are neither isolated renderer CPU nor FPS. Keyed churn alternates remove and re-insert epochs, so its samples describe two populations.

A separate warm local-edit/callback-only probe reports layout, text and retained rebuild deltas. The ordinary browser build records a separate Chromium worker sampled-JS-heap allocation window, which is **not** a Rust/WASM allocator measurement. The benchmark also runs a separate profiling-enabled GUI build with host `ippProfile` hooks for mixed-action core CPU timing, WASM linear-memory capacity and allocator categories by semantic name, plus distinct warmed 24-idle-frame CPU and allocator windows for each panel-count sweep. CPU distributions measure wall time per actual whole-Host frame across all participating Worlds: `evaluationMs` wraps the Host tick including presentation, while `hostFrameMs` covers the wider worker step. Linear-memory capacity is a high-water value, not each sweep's retained footprint; capture diagnostics provide GUI/cache resident bytes. Raw stage slots are positional and must not be compared across revisions. Native has no corresponding core CPU/allocator sample in this harness; native GPU-resident bytes remain in capture diagnostics. Missing diagnostic groups are unavailable, never zero.

Default Chromium may use SwiftShader; set the explicit ANGLE backend and verify the report's unmasked device identity before describing browser measurements as hardware. Native GLES also requires the reported EGL/device identity. Preserve the pipeline evidence directory, logs and exit status with each report. Capture and allocation/profiling windows must remain separate from timings when extending this benchmark. When comparing reports from different revisions, run them on the same machine, profile, assets, viewport, DPR and warmup.
