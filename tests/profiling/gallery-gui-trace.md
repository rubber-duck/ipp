# Gallery CPU traces

Use `python tools/ipp.py trace browser --scene gallery-gui --max-events 100000 --max-artifact-bytes 134217728 --output target/performance/gallery-trace-browser --software` for a bounded semantic capture of a physical GAIN slider drag through the generated worker Host. Use `python tools/ipp.py trace native --scene gallery-gui --max-events 100000 --max-artifact-bytes 134217728 --output target/performance/gallery-trace-native --egl-dir /usr/lib64 --software` for the same gallery mounted through its maintained native GLES driver, with a public GAIN option update. The native renderer remains independently selected by the Host; `--software` selects Chromium where the pipeline uses it. These commands are instrumentation diagnostics. Ordinary benchmark timing remains separate.

`--max-events` is the explicit capacity of the drop-new complete-span recorder. `--max-artifact-bytes` independently bounds the Host's retained diagnostic JSON; the default is the reader's 16 MiB limit. Large event capacities need enough artifact space for semantic identity metadata. Event overflow reports `droppedEvents`; insufficient artifact space fails the capture and still releases owned resources. Neither setting is a distribution-size budget or a limit on an ordinary World.

Open `trace.json` in Perfetto or a Chrome Trace Event viewer. It contains complete World, System and fixed CPU spans on capture-scoped Host/thread tracks. Exact decimal Host, World, incarnation, composition, sequence and frame identities remain in event arguments alongside raw nanosecond stamps. Host frame ordinals are independent of renderer draw sequences. `profile-capture.json` preserves the raw envelope, and `manifest.json` records the workload, retained/dropped counts, caller clock participant and image evidence. The maintained `gallery-trace` correctness suite uses a small recorder capacity to exercise overflow through real worker/native transports and completed images.

The visual timeline starts at the capture's core monotonic boundary. Client control requests supply before/after reference-clock bounds with uncertainty, a per-reader context identity and its actual `performance.timeOrigin`. API names do not establish a shared epoch. `--cdp` optionally retains a separate worker CPU profile; browser/CDP tracks are explicitly unavailable by default. An adapter must measure their clock relation before merging them. GPU query durations remain metadata with their origin frame/context; they are not CPU spans or calibrated GPU timestamp tracks. The exporter validates clocks, identities, event order and capacity instead of reconstructing a timeline from aggregate counters.

The fixture builder resolves product imports from this checkout and records input paths in `target/gallery-trace/fixture-inputs.json`. The browser helper owns capture control on the live viewer Host; the native reader belongs to the runner's observer connection. Full arrays stay in JSON artifacts rather than capped operation logs. Failure reports and before/after images remain in the selected output, and every owned gallery session, World, connection and Host is cleaned up.
